# ADR-0004 产品定位面向个人而非企业团队

**状态**：已采纳
**日期**：2026-08-13

## 背景与约束

目标岗位是**企业向**的 AI 应用 / Agent / 全栈开发（对标腾讯 WorkBuddy 一类的团队内部助手）。
最初的方案也是企业知识工作台。

但立项时发现一个绕不开的问题：**企业向项目拿不到真实数据**。

只能用 LLM 合成企业制度文档、会议纪要、工单，然后基于合成数据标注评测集。
这条路的问题在于：

- 合成语料的 gold answer 本质上是"模型出题模型答"，标注质量存疑
- 没有真实用户 → 没有真实 badcase → 反馈优化闭环只能是空转
- 面试官一问"数据哪来的"，含糊其辞就前功尽弃

而"效果评估与反馈优化闭环"恰恰是本项目最核心的差异化（[ADR-0003](0003-自建评测框架.md)）。
**用假数据做的评测闭环，是把项目最强的部分建在沙子上。**

## 决策

产品定位改为**个人知识副驾**：面向知识工作者个人，语料是作者自己读过的论文、笔记、剪藏。

**明确不实现**多用户与权限系统，但把扩展点具体写清楚
（[02 架构设计 §7](../02-架构设计.md)）。

## 考虑过的替代方案

| 方案 | 优点 | 放弃理由 |
|---|---|---|
| **企业向 + 合成数据** | 与 JD 表面更对口 | 评测闭环是假的，项目最强的部分变成最弱的部分 |
| **企业向 + 公开企业语料**（年报、招股书） | 数据真实 | 作者不是这些文档的真实用户，无法判断答案质量，标注只能靠对照原文机械比对，做不出多跳与时效类的高质量题目；且依然没有真实使用场景 |
| **个人向 + 假装是企业向叙事** | 两头讨好 | 经不起追问，比诚实定位更糟 |

## 接受的代价

1. **与 JD 的表面契合度下降**。需要在简历和面试中主动说明选择理由。
   → 应对：把它讲成一个**技术判断**而非妥协（见下）
2. **多用户、权限、租户隔离这些企业级话题没有实现**。
   → 应对：[02 §7](../02-架构设计.md) 逐条写清"要支持团队需要改什么、难点在哪"。
   能说清扩展路径，等价于证明了对企业场景的理解
3. **并发与规模不会被真实检验**。
   → 应对：如实承认，并说清瓶颈在哪（[ADR-0012](0012-退役postgres与redis改用本机文件.md) 接受的代价 §3，以及 [02 §7](../02-架构设计.md) 的扩展点表）

## 为什么这反而是加分项

技术栈与企业场景 **100% 重合**：RAG、Agent、记忆、评测、成本治理一样不少。
差别只在权限模型和多租户——而这两点用一页文档就能说清楚。

换来的是三样买不到的东西：

1. **评测数据是真的**：语料是自己读过的，所以有能力亲手标注 gold answer 和 gold span
2. **badcase 是真的**：每天真实使用，反馈闭环里流的是真实失败样本
3. **产品思维有落点**：自己是用户，才知道哪个交互别扭、哪次回答让人不敢信

面试时这段话本身就是答案：
> "我知道岗位是企业向的。我选个人场景，是因为评测闭环是这个项目的核心，
> 而闭环需要真实用户和真实标注。用合成数据我可以做得看起来更像企业产品，
> 但那样最关键的部分就是假的。企业化需要补的东西我写在架构文档里了——
> 主要是 ACL 前置过滤和连接器的权限同步，后者是真正的难点。"

## 后续影响

- 数据模型去掉 `workspace_id` 与 `acl`，改为 `source_id` + `tags`（[03](../03-数据模型.md)）
- 场景重新设计：周报汇总 → 文献综述整理；组织记忆图 → 个人知识图谱
- 记忆系统的权重上升：个人助手里"它了解我"是不可替代的核心价值
- 新增成功标准：**作者自己连续使用 ≥ 30 天**（dogfooding 的硬证据）
