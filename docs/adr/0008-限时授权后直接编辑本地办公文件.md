# ADR-0008 限时授权后直接编辑本地办公文件

**状态**：已被 ADR-0009 与 ADR-0016 取代；独立工作台和格式专用执行器均已退役
**日期**：2026-08-18

## 背景与约束

WorkPilot 需要让 owner 在前端输入自然语言指令，修改电脑中的 Markdown、Word 和 Excel 文件。产品是单用户本地知识工作台，不是远程文件管理器，也不应把模型暴露为任意文件系统写入或命令执行入口。

用户明确要求：不要为每次修改增加 accept/reject 确认；应先申请权限，授权后直接写入。同时本地文件可能正被 Word、Excel 或 Obsidian 修改，Office 二进制格式也不能安全地按纯文本覆盖。

## 决策

采用 owner 会话绑定的 `local_office_write` 限时授权。授权有效期内，受限工作区中的编辑指令通过格式专用执行器直接写回，不做逐操作确认。

- 可写范围同时受已登记且启用的 `local_dir` source 和 `LOCAL_LIBRARY_PATH` 约束。
- Markdown、Word、Excel 分别使用文本、`python-docx` 和 `openpyxl` 执行器。
- 模型只输出白名单 JSON 操作，不提供文件路径、shell 或通用代码执行能力。
- 写入前执行基线哈希冲突检查、恢复副本、临时文件格式验证和原子替换。
- `.xlsx` 在写入前检查 OOXML 部件；含图表、图片、透视表、图表工作表或切片器时
  fail closed，避免 `openpyxl` 往返静默丢失内容。公式仅允许安全函数白名单，并拒绝 DDE、
  外部工作簿和联网引用。
- 恢复副本按源文件保留最近固定数量，避免长期编辑无限占用用户磁盘。
- 授权默认有效 1 小时，可撤销，并在 owner 会话失效后失去意义。载体原为 Redis，[ADR-0012](0012-退役postgres与redis改用本机文件.md) 之后是进程内的 `dict[sha256(token), 到期时刻]`。

## 考虑过的替代方案

| 方案 | 优点 | 放弃理由 |
|---|---|---|
| 每次修改展示 diff 并确认 | 单次风险最低 | 不符合连续办公指令的交互要求；高频确认会让工作台不可用 |
| 给进程任意文件系统写权限 | 实现简单，路径自由 | 权限范围过大；提示注入或路径伪造会直接扩大到整台电脑 |
| Office 文件统一转纯文本后覆盖 | 模型接口统一 | 会破坏 OOXML 结构、样式、公式、合并关系与元数据 |
| 通过桌面自动化控制 Word/Excel | 所见即所得 | 依赖 GUI、焦点和应用状态，难测试、难恢复，也不适合服务端部署 |
| 首次授权永久有效 | 操作最少 | 会话被窃取后的影响时间无限，且难以表达当前真实授权意图 |

## 接受的代价

- 在授权窗口内，合法但错误的用户指令可能立即改变文件；主要恢复手段是隐藏备份与外部版本控制，而不是修改前确认。
- Word 段落整段替换无法完整保留复杂的多 run 混排样式；Excel 首版只修改简单工作簿的值与
  安全公式，不改版式和结构；复杂 OOXML 功能在编辑前明确拒绝。
- ~~需要 Redis 才能授予和校验权限~~ → 现在没有外部依赖，但**进程重启即全部失效**。两种形态都是 fail closed，只是失效的触发条件从「Redis 故障」变成了「重启」——对一个限时授权来说，后者反而更符合直觉。
- `.doc`、`.xls`、`.xlsm` 与 `.pptx` 暂不支持。
