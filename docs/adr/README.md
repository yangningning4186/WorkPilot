# 架构决策记录 (ADR)

记录**为什么这么选**，而不是**选了什么**——后者看代码就知道，前者只存在于当时的脑子里。

面试官问"为什么用 X 而不是 Y"时，这里就是答案。
一条 ADR 必须包含：当时的约束、考虑过的替代方案、**放弃替代方案的具体理由**、
以及接受了什么代价。

只写"不可逆或代价高"的决策。选个日志库不需要 ADR。

## 模板

```markdown
# ADR-XXXX 标题

**状态**：提议中 / 已采纳 / 已废弃 / 被 ADR-YYYY 取代
**日期**：YYYY-MM-DD

## 背景与约束
当时面临什么问题？有哪些硬约束（时间、算力、人手、已有选型）？

## 决策
一句话说清做了什么选择。

## 考虑过的替代方案
| 方案 | 优点 | 放弃理由 |

## 接受的代价
这个选择让我们失去了什么？什么时候需要重新审视？

## 后续影响
对其他模块的连带约束。
```
