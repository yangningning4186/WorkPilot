# 13 · Cowork Office 文件能力

> **当前契约（2026-08-22）**：Office 文件不再拥有格式专用正式工具。Cowork 通过
> `docx` / `xlsx` / `pptx` / `pdf` 格式 Skill、受控本机 Shell 和工作区 Artifact 完成任务。
> 独立办公工作台、`inspect_office_file`、`edit_office_file`、`edit_word`、`edit_excel`
> 与 `create_native_artifact` 均已退役。

## 1. 为什么改成 Skill + Shell

格式专用工具把每一种文档操作都固化成 JSON schema。它能严格限制动作，但会形成三类问题：

- 每加一种版式、图表或 OOXML 特性都要扩协议、执行器和模型提示；
- 模型同时面对“先扫描、再 inspect、再 edit”的人为状态机，容易在 schema 之间空转；
- Python 生态已有成熟格式库，重复包一层窄协议反而损失表达力。

现在把“怎么正确处理某种格式”放进可演进的 Skill，把“真正执行代码”交给本机 Python/CLI，
把“用户最终拿到什么”收敛到工作区 Artifact。工具协议只保留通用边界，不再理解段落、单元格
或幻灯片操作。

## 2. 标准执行链路

```text
用户目标
  → list_files 定位输入
  → load_skill("docx" | "xlsx" | "pptx" | "pdf")
  → read_text_file / write_text_file 准备数据与一次性脚本
  → run_shell 在已授权工作区执行 Python/CLI
  → 有界扫描本轮新增或修改文件
  → 格式验证 + SHA-256 + Artifact 登记
  → 客户端预览、打开或下载
```

四个出厂格式 Skill 分别约束推荐库、结构保留、公式/版式注意事项、临时文件验证和交付命名。
项目可以在 `.workpilot/skills/` 覆盖格式流程，例如固定企业模板、字体、页眉或校验脚本。

默认生成新文件。只有用户明确要求覆盖源文件时才允许原地修改；格式 Skill 要求脚本先做恢复
副本，在同目录临时文件中完成写入，重新打开验证成功后再 `os.replace`。这是脚本工作流约束，
不再伪装成通用工具层能够理解所有格式语义。

## 3. 为什么选择本机持久 Shell

WorkPilot 是桌面 Cowork，不是远程多租户执行平台。文档通常已经在本机目录里，格式库、字体、
模板和企业 CLI 也都属于本机环境。采用每轮隔离沙箱会丢失 `cwd`、虚拟环境和刚准备好的脚本，
还需要重复挂载目录与安装依赖，因此选用会话级持久 PTY：

- PTY 存活期间保留 `cwd`、`export`、venv 和 shell 函数；
- 每次完成持久化最后 `cwd`；进程重启后只恢复 `cwd`，明确报告环境变量已丢失；
- Office 任务使用前台命令，后台任务不会自动发现交付物；
- sidecar 启动的 Python 会优先进入 `PATH`，可直接使用随应用安装的格式依赖。

这不是 Full Access。模型必须先拥有 `shell.execute`，`cwd` 必须落在会话已授权的读写 root；
未命中可信 allowlist 的命令仍进入审批卡片。目录授权不会自动继承 Shell、网络或外部系统能力。

## 4. 产物与安全边界

前台 `run_shell` 执行前后会对授权 root 做有界快照，自动发现新建或变更的 DOCX、XLSX、
PPTX、PDF 和可信文本格式。扫描器：

- 不跟随符号链接，跳过隐藏目录、依赖目录、版本库与备份目录；
- 限制遍历条目、候选文件数、单文件大小和 OOXML 解压规模；
- 用 `python-docx`、`openpyxl`、`python-pptx` 或 PyMuPDF 重新打开原生格式；
- 校验通过后计算 SHA-256 并登记 Artifact；失败只产生明确警告，不把损坏文件包装成交付物；
- Artifact 扫描或登记失败不会重放已经执行过的 Shell 命令，避免副作用重复。

Shell 本身仍按 `effect=external` 取得 `tool_invocations` 租约。Artifact 登记是执行后的事实发现，
不是另一条写文件旁路。

## 5. 明确接受的代价

- 旧格式工具提供的操作白名单和自动 baseline 冲突检查不再存在；保护责任转移到格式 Skill、
  命令审批、临时文件/备份流程和版本控制。
- 工作区扫描只能发现支持的后缀；后台进程稍后生成的文件需要以前台命令确认或显式登记。
- 格式“能重新打开”不等于像素级排版正确，复杂交付物仍需预览或用目标 Office 应用复核。
- 当前开发态可直接复用 backend venv；发布态若不携带 Python 运行时，必须随 sidecar 打包等价
  的格式 CLI，不能在任务中临时联网安装依赖。

架构决策与替代方案见 [ADR-0016](adr/0016-格式Skill持久Shell与工作区产物.md)。
