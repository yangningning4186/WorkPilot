# E1 · 分块策略四方案正式对照（2026-08-16）

## 结论先行

本轮**保留 `heading` 为默认分块策略**，不切换到 `fixed`、`recursive` 或
`semantic`。原因不是 heading 已经统计显著胜出，而是：

- heading 在 core-dev 的检索质量点估计整体最高，在 english-dev 也与 semantic 的
  Recall 持平且 nDCG/MRR 更高；
- semantic 在中英文两层都显著减少检索上下文 token 和延迟，是明确的效率候选，
  但 core-dev 生成轨尚未证明端到端质量显著优于 heading；
- fixed 的 overlap 在两种语言上稳定增加冗余、token 与延迟，没有换来显著质量收益；
- recursive 没有表现出预期的质量/成本折中，core-dev 生成 token 还显著增加。

这是一项**阶段采纳决策**：40 条人工集已经完成检索轨，生成轨目前只覆盖
`core-dev/human` 20 条。English 生成未跑，不能写成“40 条端到端结论”。

## 实验前假设

1. H1：论文和技术文档的标题结构是作者提供的语义边界，heading 的检索质量可能最好。
2. H2：semantic 会以更细的块降低上下文成本，但质量未必超过 heading。
3. H3：fixed 的 64-token overlap 会产生可测的冗余，且未必转化为召回收益。
4. H4：recursive 可能在结构保持与块大小之间形成工程折中。

这些假设在跑批前已写入设计与分层验证计划；本报告保留被数据推翻的部分。

## 异常样本与归因

- English 有 8 条策略间 Recall 分歧达到 50%，core 有 3 条，英文题对边界更敏感。
- English 有一条 table 题 heading=0、其他三策略=1，后续应检查 heading 的表格邻接
  与 rerank 排位；小切片不足以支持改默认。
- core 有一条四策略都未命中的题，应归因语料覆盖或标注，而不是分块策略。
- fixed 的负结果跨语言复现，说明 overlap 冗余是策略自身的稳定代价。
- recursive 的检索质量没有形成折中，生成 token 又显著增加，H4 被本轮数据推翻。

## 假设判定与采纳

| 假设 | 判定 | 决策 |
|---|---|---|
| H1 heading 质量最好 | 方向支持，统计未确认 | 保留默认，避免过度结论 |
| H2 semantic 更省上下文 | 两层显著支持 | 保留为效率候选，扩集复验 |
| H3 fixed overlap 增加冗余 | 两层显著支持 | 不采纳 fixed 为默认 |
| H4 recursive 是工程折中 | 未支持，且生成 token 显著变差 | 不采纳 |

因此 E1 的阶段结论是：**heading 继续作为稳健默认；semantic 进入下一轮候选，等待
English 生成或扩充后的 test 集确认；fixed 与 recursive 不进入默认候选。**

## 结论边界与后续门槛

- 检索结论覆盖 40 条 human，但按 core/English 分层 bootstrap，不制造合并 CI。
- 端到端结论只覆盖 core-dev 20 条；若要宣称跨语言生成收益，必须补 English 生成轨。
- 生成质量目前是规则轨；语义正确性仍需完成 Judge 校准后复核。
- 这是 dev 集阶段决策，不是最终 test 结论；W3 的 120 条 dev/test 扩集仍是硬门槛。
