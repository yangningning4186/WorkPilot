# J0 · Judge 校准与 120 条扩集预检（2026-08-16）

## 结论先行

Judge 校准工程链路已经可用，但**正式校准尚未开始**：当前只有 20 个唯一生成 case、
覆盖 4/7 类，未达到 80 条门槛，也没有新的模型发送授权。系统因此保持 `pending`，
没有调用任何 Judge 模型，也没有产出 Kappa 数字。

120 条扩集方面，已经完成可重复的 dev/test 分割、候选构建、七类标注契约和独立审计，
但首版 80 条自动草稿被内容质量门禁拒绝。数据库仍只有原 40 条 human，没有把低质量
草稿写成 candidate 或 human。这次拒绝是预期的 fail-closed 行为，不是 120 条已完成。

| 项目 | 门槛 |
|---|---|
| 数据规模 | dev 100 / test 20；旧 40 只进入 dev |

| 语言 | 新增 dev 中英文各 30；test 中英文各 10 |

| 模型 | 显式 provider/model，fallback=false，逐调用记录实际身份与 raw/reason/token |

### 复核修正：temporal 判据原本是坏的

首版 `temporal_without_historical_contrast` 按类别无条件打标，没有任何内容判断。
后果不是「严格」而是**死锁**：只要 120 条设计里有 temporal，内容门禁就永远非空，
`--apply` 永远失败，人工逐条改写也过不了。这不是 fail-closed，是坏掉的闸门。

已改成真实判据，满足任一即通过：证据跨 ≥2 个 version，或问题含明确的时间对照词
（`相比 / 变化 / 此前 / 更新前 / 改为 / 不再`、`compared with / changed from /
previously / no longer` 等）。词表刻意不收 `之前 / since` 这类过宽的词，否则改写者
随手加一个词就能骗过门禁。

当前 12 条 temporal 草稿**仍全部被判定**——它们确实是快照式提问（"At the time this
corpus version became active, what did X report..."），本来就没有跨时间点比较。
区别在于这个 12 现在是量出来的，且存在明确的通过路径。

## Judge 工程预检结果

校准工具已经实现四段式闭环：

1. `prepare`：从唯一 generation cases 导出冻结样本、人工标签模板和 rubric；
2. `run`：只有显式授权才允许调用模型，严格核对实际 provider/model；
3. `import`：以版本化 `judge_calibration/rubric/metric` namespace 合并写回，不覆盖
   M0 的 `human_label.citation_accuracy`；
4. `calibrate`：只用未参与 rubric 调整的 validation split 执行 QWK/accuracy 门禁，
   同时报告混淆矩阵、标签边际、类别切片、bootstrap CI 与逐条分歧。

### 复核修正：类别切片改为只诊断不设门禁

首版把 `min_slice_accuracy = 0.70` 直接作用在类别切片上，且没有最小样本量保护。
按预注册规模推：80 case → validation 20 → 7 类 → 每类 2~3 条。3 条错 1 条 = 0.667，
2 条错 1 条 = 0.5，都必然跌破阈值。这个门禁报出来的是「样本太少判不了」，
却写成了「Judge 在这个类别上不合格」——把抽样噪声当成质量结论。

要让逐类判定有意义，需要每类至少 5 条可解读样本 ⇒ validation ≥ 35 ⇒ 约 140 个
Judge case，**超出 120 条数据集规划本身**。因此采纳的方案是：

- 验收只卡 validation 的**整体** QWK / accuracy；
- 类别切片照常计算并报告，标注 `interpretable` / `below_threshold` /
  `insufficient_samples`，但不进 `gate_failures`；
- 报告强制携带一句 caveat：**类别级可靠性未验证，通过不代表每个类别都达标**；
- 判据一直在算，数据规模上来后 `--slice-gate-policy enforce` 一个开关即可打开。

**这是一个明确的能力缺口，不是已解决项**：在 120 条规模上，我们不会知道 Judge
是否在某个类别（尤其 table / temporal / agent_task）系统性偏斜。切片数值只能当
方向性线索用于人工归因，不能写进任何对外结论。

## 阶段决策

- 采纳扩集与 Judge 的工程基础设施和质量门禁。
- 不采纳首版 80 条自动草稿，不写入数据库，不升级 human。
- 不用四策略的重复答案凑 80 个 Judge case。
- 下一步先逐题改写并人工复核新增 80 条；若使用内网模型辅助改写，必须取得覆盖新增
  问题、gold answer、证据与答案的新授权。
- agent_task 的固定工作流和实际产物闭环完成前，七类 Judge 正式验收继续保持 pending。
  注意这是一条无条件规则（`agent_task_execution_closure_pending`）：**凑齐七类反而
  必然触发它**。所以要么整体验收推迟到闭环完成，要么先做六类验收拿中间结论——
  「凑够 80 条就能验收」的读法是错的。
- 类别级可靠性在 120 条规模上不做验收（见上），作为已知缺口带入下一阶段。
