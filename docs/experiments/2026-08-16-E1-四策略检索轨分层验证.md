# E1 · 四策略检索轨中英文分层验证（2026-08-16）

## 背景与实验前预判

项目设计文档在 E1 跑批前已经给出三个预判：

1. `heading` 会更适合论文和技术文档，因为标题结构是作者提供的语义边界；
2. `semantic` 可能以更细的块换取更低的上下文成本，但质量未必超过 `heading`；
3. `fixed` 的 64-token overlap 会带来可测的上下文冗余。

`core-dev/human` 首批已经完成，但它只有 20 条题，不能代替完整 40 条人工集。
本次只在独立的 `english-dev/human` 上复现完全相同的四策略检索实验，再与
`core-dev` 做语言分层方向检查。两个数据集分别 bootstrap，**不拼接样本、不报告
一个伪造的 40 条合并置信区间**。

## 口径

| 项目 | 固定值 |
|---|---|
| 检索 | dense + lexical `ts_rank` + RRF(k=60) + 本地 rerank |
| reranker | `BAAI/bge-reranker-v2-m3`，title + heading + content |
| embedding | `bge-m3:latest`，revision `sha256-daec…3062c`，1024 维 |
| Top-K / diagnostic-K | 10 / 50 |
| 固定检索预算 | 4000 Unicode token |
| span overlap θ / α-nDCG α | 0.5 / 0.5 |
| 统计 | paired percentile bootstrap，10,000 次，seed=12345，95% CI |
| fallback | false；任一失败即不进入矩阵 |

两批的受控配置逐键核对后无差异；允许不同的只有 dataset、dataset fingerprint 与
runner git SHA。core-dev 使用 `7d7b9bb`，english-dev 使用 `6a7e51e`，两者之间仅增加
任务清单文档提交，评测实现未变化。

## 语言分层观察

1. **heading 的质量优势方向在英文层更强，但仍未显著。** fixed 的 Recall 点差从
   core-dev 的 -3.12pp 扩大到 english-dev 的 -25.00pp，recursive 从 -6.25pp
   扩大到 -21.88pp。n=16 的区间仍很宽，只能作为扩集方向，不能作为最终胜负。
2. **semantic 在英文层追平 heading 的 Recall。** 两者都是 81.25%；semantic 的
   nDCG/MRR 点估计略低，但同时显著减少 568 个 Top-K token 和 256.9ms 延迟。
   这与“semantic 是效率候选”的预判一致。
3. **fixed 的负担跨语言稳定复现。** overlap 没有转化成显著质量收益，却在两个层次
   都显著增加冗余、上下文 token 和延迟。H3 得到重复实验支持。
4. **recursive 没体现预期的工程折中。** 英文层质量点估计接近 fixed，且 token
   显著高于 heading；core 层延迟还显著更高。当前没有采纳它替换 heading 的证据。
5. **类别切片提示边界敏感性。** english-dev single_hop 的 budget Recall 为
   heading 100%、semantic 85.71%、fixed/recursive 42.86%；table 则是 fixed、recursive、
   semantic 100%，heading 80%。这说明标题边界对英文单跳题有利，但个别表格证据可能
   被 heading 组织方式漏掉。切片很小，只作为 badcase 路由。

## 异常样本

- english-dev 有 8 条样本的策略间 Recall 分歧达到 50%，core-dev 为 3 条；英文集对
  分块边界更敏感，适合继续扩充 single_hop 与精确数字题。
- english-dev 没有“四策略全未命中”样本，core-dev 有 1 条；后者更像语料或标注问题，
  不应归因给分块策略。
- english-dev 有一条表格题 heading=0、其余三策略=1，应检查 heading chunk 的表格邻接
  与 rerank 排位；本报告只记录 badcase，不在本线程修改检索实现。

## 结论边界与阶段决策

- H1（heading 质量最好）：**方向性支持，统计上未确认**。heading 在 core-dev 的质量
  点估计全部最高，在 english-dev 与 semantic Recall 持平且 nDCG/MRR 更高，但所有质量
  CI 都跨 0。
- H2（semantic 更省上下文）：**两层显著复现**。semantic 是当前最明确的效率候选，
  但是否替换默认仍需生成轨与更大样本。
- H3（fixed overlap 增加冗余）：**两层显著复现**。当前没有证据证明额外冗余值得。
- 当前继续保留 `heading` 为默认；这不是“heading 已显著胜出”，而是质量风险最低且
  尚无充分证据更换默认。最终决策必须等待四策略生成轨和扩充后的 dev/test。
