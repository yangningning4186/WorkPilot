## 0. 为什么是口径 B

原计划的口径 A 是"各档分别与人工标签比 QWK，谁高谁赢"。**跑不出结论**：

- 唯一一份 70 条标签是助手起草、作者复核的。`human-labels-provenance.json`
  自己写明："助手与 Judge 同为大模型，其一致性高于真实人机一致性，
  **QWK 会被系统性高估**"。
- 而 heavy 在那份标签上已经是 **accuracy 1.0000 / QWK 1.0000**——天花板顶死了，
  main 最好也只能打平。**这个实验在当前标签上没有分辨空间。**

所以改口径 B：**不问谁判得对，只问两档判得一样不一样。** 它不需要新标签，
且足以支撑成本决策——如果判决高度一致，换成 main 改变的只是成本，不改变结论。

> **这个口径证明不了两者都判得准。** 准不准仍要等独立人工盲标（口径 A）。
> 报告里任何地方都不许把"一致"写成"准确"。

## 1. 一个先决条件：main 开着思考链根本跑不了 Judge ★

第一次跑 main 直接失败，0/70：

```
Judge 响应重试 1 次后仍无法解析: ... raw="Here's a thinking process:\n\n1. **Analyze User Input:** ..."
```

`main` 档默认 `enable_thinking=true`，思考链顶在 JSON 前面，严格解析器直接拒绝。
而 `judge_calibration run` 的 CLI **不带这个开关**，只能吃端点默认值——
于是"同一个 rubric 在两档上跑"根本不是受控对照，测出来的是"能不能闭嘴"。

修复：给 `run` 子命令补 `--enable-thinking / --no-enable-thinking`（tristate，
不给仍用端点默认）。关掉思考链后 main **70/70 一次通过，0 次修复重试**。

> 教训与 E2 同构：**先确认判据量的是不是你要的东西。**
> 不修这个开关，这个实验会得出"main 完全不能当 Judge"的错误结论。

## 3. 三条结论

### 3.1 heavy 在 Judge 上是确定性的——G0 的推测成立 ★

C 台账结论 2 说"heavy 在 temperature=0 下不可复现"（引用对齐跨度 13.5pp）。
[G0](2026-08-17-G0-门禁准备与噪声地板.md) 把它收窄为：抖的是**生成**槽位，
C7 把 heavy 放在证据门控上时四个指标逐位一致；机制是**短离散输出 vs 长自由文本**。

本实验直接验证了这条推测，而且给出了一个更干净的证据：

**heavy 两次重复的判决逐条相同（一致率 1.0000），但输出 token 从 14,142 变成 12,731。**
也就是说——**理由文本在抖，离散判决没抖**。这正是"短离散量对采样噪声鲁棒"的定义。

于是 C 台账那条操作规则可以放宽一档：
**"任何用 heavy 产出的指标都必须多次重复取中位数"应改为"任何用 heavy 产出的
长文本指标必须重复"**；离散判决类不需要。

### 3.2 main 与 heavy 的分歧是**单向**的，而且落在作者自己标记的争议样本上 ★

混淆矩阵（行 = heavy，列 = main）：

```
          main=0   main=1
heavy=0      15        2
heavy=1       0       53
```

**分歧全部是 heavy=0 / main=1，没有一条反向。** main 系统性更宽松。
两条的机制一致——heavy 因"遗漏参考答案里的必要说法"扣分，main 认为"已覆盖必要要点"：

| example_id | 类别 | heavy 的理由 | main 的理由 |
|---|---|---|---|
| `44c0504190e5…` | global | 遗漏了参考答案的第二种必要说法 | 准确覆盖了必要要点 |
| `f394e53e6101…` | table | （覆盖清单，判为不足） | 未提 Langfuse 但提供了更详细的模块 |

**最值得记的一点**：这两条 **都在** `human-labels-provenance.json` 的
`explicitly_adjudicated` 列表里——那是作者当初标注时自己挑出来"判据存在争议、
需要逐条裁定"的 8 条之一。

两个独立模型的分歧点，与人类事先标记的模糊点重合。这说明这 2 条不是模型缺陷，
**是 rubric 在这些点上本来就没定义清楚**。要提高一致性，该改的是 rubric，不是换模型。

### 3.3 成本：输出 token 2.8×，墙钟 8×

| | heavy | main | 倍数 |
|---|---:|---:|---:|
| 输出 token | 14,142 | 5,027 | **2.8×** |
| 70 条墙钟 | ~306s | 37s | **8.3×** |

输入 token 基本持平（49,055 vs 46,557），差异全在输出——heavy 写的理由长得多。

## 4. 决策

**有条件采纳：Judge 降到 main。**

条件有三条，缺一条就退回 heavy：

1. **必须显式关思考链**（`--no-enable-thinking`）。不关就是 0/70。
2. **只覆盖 `answer-correctness-binary.v2` 这一个 rubric。** 换 rubric 要重跑本实验；
   两档在别的判据上未必还这么一致。
3. **不作为"main 判得准"的依据。** 一致 ≠ 准确。正式验收仍需独立人工盲标（口径 A）。

**边界（必须写出来）**：

- QWK 的 95% CI 下界是 **0.7842**，低于 J0 定的 0.85 门槛。n=70、分歧只有 2 条时
  区间就是这么宽——**点估计 0.9191 好看，但它撑不起"已达标"这句话**。
- 标签分布 53:17 偏斜，QWK 对偏斜敏感，这也是它比一致率低那么多的原因。
- 全部结论只在这 70 条上成立，且这 70 条与 dev 集同源，不是独立留出。
