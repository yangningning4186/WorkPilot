# A0｜固定综述 Agent 可靠性骨架

**日期**：2026-08-16  
**性质**：工程可靠性基线，不是模型质量实验  
**数据边界**：只使用确定性 fake 和隔离测试库；未访问 10 条 test，未向外部模型发送项目数据

## 目标

在引入自由规划与 reflection 前，先验证固定综述的三条基础性质：执行状态可恢复、人工确认前
没有副作用、恢复或重复确认不会重复写入。

## 实现基线

- `agent_runs.workflow_type` 区分 `answer` 与 `literature_review`
- 新增 `agent_plan_steps`、`agent_attempts`、`tool_invocations`、`agent_checkpoints`
- 固定 LangGraph：筛选 → 抽卡 → 分组 → 对比 → 生成预览 → HITL → 写回
- 每个只读节点完成后落 attempt、SSE event 和完整 JSON checkpoint
- `write_note` 使用稳定幂等键、租约/CAS、临时文件、`fsync`、原子 rename 和 `effect_ref`
- 输出限定在 `AGENT_OUTPUT_PATH` 内的相对 `.md` 路径，拒绝路径穿越与 symlink 逃逸
- 创建与 resume 端点要求 owner admin，同时继续校验 demo conversation/run 所有权

## 故障注入与结果

| 场景 | 预期 | 结果 |
|---|---|---|
| compare 节点失败后换新执行器 | 从 compare 继续，不重跑前三步 | 通过 |
| `in_flight` 租约过期 | CAS 换 owner，`retry_count + 1` | 通过 |
| rename 后、DB succeeded 前失败 | 文件内容相同则只补结算，不再 replace | 通过 |
| 用户拒绝写回 | plan step skipped，磁盘零写入 | 通过 |
| 同一 token 重复批准 | 只保留一次 `run.done`，文件 inode/mtime 不变 | 通过 |
| `../outside.md` / 非 `.md` | fail-closed | 通过 |
| 调用数用尽后再发一次请求 | 发请求前拦下，`dispatched` 不增 | 通过 |
| token 预留超上限 | 调用前拦下，实际结算按真实用量而非预留量 | 通过 |
| 墙钟跨 `waiting_human` 恢复 | 人工确认的 10 分钟不计入，只累计执行分段 | 通过 |
| 熔断后再投一次队列 | 终态不再执行任何节点，工具调用为空 | 通过 |
| 节点失败但已烧 token | 消耗与 checkpoint 同事务落库，重试不清零 | 通过 |

当前完整后端测试共 306 项，Ruff、mypy、前端 ESLint 与 TypeScript 检查均通过；固定综述
前端专项 Playwright 7/7、全量 30/30。可靠性测试不调用真实模型，结果只证明状态机、
副作用边界与预算判定，不代表综述内容质量。

## 预算熔断的一处设计返工

首版把 checkpoint 里的整份 budget 快照接管回计量器，被
`test_budget_trip_lands_terminal_state_before_any_human_confirmation` 直接照出来：
**上限也被从 checkpoint 抄了回来**。这意味着给某个 run 提额之后恢复执行会继续用旧上限，
提额静默失效——而且因为熔断本来就少见，这种失效在真实使用里几乎不可能被发现。

改为只接管 `used_wall_ms` 这一维（它是唯一只存在于 checkpoint 的量），上限与
token/调用数消耗一律以 `agent_runs` 行为准。四条完整口径记在
[05 §预算熔断的四条口径](../05-Agent设计.md)。

## 杀真实 worker 的恢复演示

单测里的"崩溃"是抛异常，进程还活着、`finally` 还会跑，证明不了失联。
`eval/worker_recovery_demo.py` 用 `SIGKILL` 打掉整个进程组：没有优雅关闭、没有 `finally`、
连接直接断，数据库那边看到的就是一个租约挂在半空的 run。

一次真实跑批（`eval/outputs/worker-recovery/kill-demo-20260816/`，48.9s）：

| 阶段 | 事实 |
|---|---|
| worker-1 完成 | `select_documents` / `extract_cards` / `group_cards` |
| SIGKILL 时刻 | `compare_documents` 处于 `running`，plan 为 done/done/done/running/pending/pending |
| watchdog | `recovery_count` 1，run 退回 `queued` 并重新入队 |
| worker-2（全新进程）执行 | `compare_documents` / `generate_preview` |
| **重跑的已完成节点** | **0 个** |
| 人工确认前的写回文件 | 不存在 |
| 终态 | `waiting_human` |

### 两个只有真跑才会暴露的 bug

1. **松开租约会把 run 变成僵尸。** watchdog 原本只清 `lease_until`，
   但 `claim_run` 的条件是 `status = 'queued' OR (非终态 AND lease_until < now())`，
   而 `NULL < now()` 是 NULL 不是 true——run 谁都抢不到，永远卡住。
   改为显式退回 `queued`。这条被 `test_watchdog_recovers_review_run_instead_of_failing_it`
   钉死。
2. **arq 按 `job_id` 去重，重投会被静默丢弃。** 被 SIGKILL 的作业在 result 键过期前
   一直占着 `review_run:{run_id}`，沿用同一个 id 重投等于没投，恢复永远不发生。
   改为恢复时用 `review_run:{run_id}:r{n}`；双跑防线仍是 `claim_run` 的条件 UPDATE，
   换 id 不放松它。

自动恢复只给**同时**满足三条的 run：`literature_review` 工作流、已落过 checkpoint、
`recovery_count` 没用完（默认 3）。普通回答仍然一律判失败——一次已发出的模型调用
是否计费无法确认，静默重放等于重复计费。
