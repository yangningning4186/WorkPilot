# 实验台账

**这是整个项目最重要的目录。**

面试官问"你做了哪些优化、分别提升了多少"时，
能打开一份逐条记录的台账，和只能口述"我做了混合检索感觉好一些"，
是完全不同的两个候选人。

---

## 四条铁律

### 1. 一次只改一个变量
两个改动一起上，指标涨了也归因不了，这次实验就白做了。

### 2. 先写假设再跑
事后编的假设没有价值，而且会导致选择性解读——
跑完再写假设的人，永远只会写出"和我预期一致"。

**假设写错了不丢人，被数据推翻的假设才是最值钱的实验。**

### 3. 负优化必须记录
这是台账里最有价值的部分。例如：

> 我以为语义分块会赢，结果在论文语料上比标题分块低 6 个点。
> 归因：学术写作的章节结构本身就是作者做好的语义分块，
> 而语义分块在公式和表格附近会误判边界。

这段话在面试里的分量，超过任何一个正向指标。
它证明了三件事：你真的跑了实验、你会归因、你不粉饰结果。

### 4. 记录 git_sha 与 config_hash
任何数字都必须能追溯到确切的代码与配置，否则半个月后自己都复现不出来。

## 噪声控制与显著性判定

LLM 输出有随机性，`temperature=0` 也不能完全消除
（batch 组成、并发调度、MoE 路由都会引入变化）。

**"跑三次取中位数"不足以支撑"显著提升"的结论。** 每个实验必须：

| 步骤 | 做法 |
|---|---|
| 1. 估噪声地板 | 固定 seed 重复跑 3 次同一配置，看指标波动幅度 |
| 2. **配对显著性检验** | 对 N 个样本的**逐样本配对差值**做 bootstrap 重采样 10000 次，给出 Δ 的 95% 置信区间 |
| 3. 判定 | **置信区间跨 0 → 写"无显著差异"**，不许写成提升 |
| 4. 分类别看 | 整体持平可能掩盖"A 类涨 B 类跌"，必须按七类分别报告 |

> 为什么是 paired bootstrap 而不是独立样本检验：
> 同一批题目在两个配置下的得分是**配对**的，配对检验能消掉题目难度带来的方差，
> 统计功效高得多——在只有一两百条样本时这个差别是决定性的。

这一条决定了台账是可信的数据，还是自我安慰。

## 成本类实验的额外要求

所有配置必须在**相同并发设定**下测量，并同时报告吞吐、并发度、GPU 利用率。
成本按整批 GPU wall time 摊销，**不能用 latency × GPU 单价**
（并发下会把共享的 GPU 时间重复计费）。详见 [07 §7](../07-模型路由与成本.md)。
