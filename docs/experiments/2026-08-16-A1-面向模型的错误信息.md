# A1 · 面向模型的错误信息对工具失败恢复的影响（2026-08-16）

## 结论先行

面向模型的错误信息**有效但不解决主要问题**。在 20 篇真实文档的 `extract_card` 上：

| 档 | 首轮失败 | 补救后恢复 | 恢复率 | 补救后失败模式改变或恢复 |
|---|---:|---:|---:|---:|
| `none`（不补救） | 14/20 | — | — | — |
| `generic`（"输出不合法，请重新输出"） | 14/20 | 0 | **0%** | 3/14 |
| `model_facing`（具体到条目的可执行指令） | 14/20 | 2 | **14.3%** | **8/14** |

恢复率 2/14 vs 0/14，样本太小，单看这一个数字不构成结论。**真正的证据是最后一列**：
通用错误下 11/14 次补救原样重复了同一个失败；面向模型的错误下 8/14 改变了失败模式
（典型是 `schema_invalid` → 修好了 schema → 撞上下一道 `quote_not_verbatim` 关卡）。
模型确实在照着指令改，只是两次补救不够穿过全部关卡。

**但首轮失败率 70% 才是这批数据最该被记住的数字。** 改错误信息是在给一个
设计有问题的工具做康复训练，不是治病。见下面的归因与 [A2](2026-08-16-A2-工具描述样例.md)。

## 口径

- 被测单元：一次 `extract_card` 调用（读一篇文档 → 输出结构化卡片 → schema 校验 +
  `evidence_quotes` 逐字校验）
- 模型：`qwen3.6-35b-a3b`（vLLM，openai_compatible），temperature=0，`max_tokens=1200`
- 三档**首轮 prompt 完全相同**，只在校验失败之后分叉；补救上限 2 次
  （与 [E5](2026-08-16-E5-evidence-gate误拒修复.md) 的 gate 同政策：只吸收单点抖动）
- 当前网关只有一个 provider，不存在 fallback 链，报告里记为 `not_configured_single_provider`
  而不是 `false`——日后有了 fallback 才不会误以为这批数据关过
- 产物：`eval/outputs/agent-error-messages/a1-20260816/`，
  `system_prompt_sha=1fddba43e8d89ab1`

### 一个必须先过的完整性检查

三档首轮 prompt 相同，那么首轮失败集合就应该一样。实测**三档的首轮失败集合逐条相同**
（`first_round_disagreement_vs_none` 两项均为空），`tool_error_rate` 都是 0.70。
temperature=0 在这个端点上是真的确定性，所以恢复率的差可以归因到补救信息，
不需要再算噪声带。

## 归因：70% 的首轮失败是什么

| 失败类型 | 首轮条数 | 机制 |
|---|---:|---|
| `quote_not_verbatim` | 6 | 模型给的 evidence_quotes 在文档里搜不到一模一样的文本 |
| `schema_invalid` | 4 | 输出把 system prompt 里的**空模板**原样抄了回来（全空串/空数组） |
| `not_json` | 4 | **`max_tokens=1200` 截断**，JSON 断在半句话上 |

第三类是纯工程问题，单独验证过：拿最长的一篇复跑，`output_tokens` 正好等于 1200，
文本停在 `TTFT(首 token 延迟)由 prefill 决定——`。任何错误信息都救不了它，
补救只是让它再截断一次。**与 [E6](2026-08-16-E6-Judge二分类rubric与70条草稿标注.md)
的 Judge `max_tokens` 是同一个坑，第二次踩。** 已把 `card_max_tokens` 默认提到 2400。

第二类指向 prompt 本身：`{"core_problem":"","method_family":"",...}` 这种空骨架
是在邀请模型照抄。这条留给 A2 单独测。

## 决策

1. **`model_facing` 进生产**，`card_error_style` 默认 `model_facing`，补救上限 2。
   理由不是那 14.3%，而是通用错误在 temperature=0 下**结构上不可能恢复**：
   不给新信息，模型的输入几乎没变，输出自然几乎没变。这一条不依赖样本量。
2. **`max_tokens` 提到 2400**，并在代码里写明原因，避免第三次踩。
3. 不据此宣称"工具错误率下降了多少"——首轮失败率没动，A1 动的只是失败之后那一段。
4. 下一轮先修工具契约本身（A2 + 逐字校验的口径），再谈补救策略。

## 一处实现返工

逐字校验原本拿**全文**核对 quote，但模型只看得到 `_bounded_document` 截断后的
30k 字符摘录。超长文档里，模型规规矩矩引用了它看到的内容，却因为引用落在
被截掉的那一段之外而判失败——冤枉的是工具不是模型。已改为对模型**实际看过的那段文本**
校验。这个 bug 在 A1 之前不会暴露，因为此前根本没有逐条记录失败类型。
