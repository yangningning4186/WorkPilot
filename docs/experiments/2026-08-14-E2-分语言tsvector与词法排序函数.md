# E2 · 分语言 tsvector 与词法排序函数三档对照（2026-08-14）

## 假设

现有词法打分是「命中词数 / 总词数」的覆盖率，无停用词表、无 IDF、纯子串匹配。
先在语料上量了一遍词频，问题很直白：

| 词 | 命中 chunk 数 / 1862 | 占比 |
|---|---:|---:|
| `in` | 1584 | 85.1% |
| `is` | 1354 | 72.7% |
| `ai` | 1347 | 72.3% |
| `and` | 1284 | 69.0% |
| `the` | 1282 | 68.9% |
| `act` | 824 | 44.3% |
| `pagedattention` | 9 | 0.5% |
| `ttft` | 12 | 0.6% |

`ai` 占 72.3% 是子串匹配的锅（命中 s**ai**d / det**ai**l / ch**ai**n / dom**ai**n）。
中文双字滑窗本来就要匹配子串所以无害，英文短 token 上就是纯噪声。
后果可复现：查询 `How does PagedAttention work in vLLM?` 的词法 Top-10 **全部得 0.667**，
**没有一条包含 `pagedattention` 或 `vllm`**——四个停用词凑满分母。
正确的 chunk 排在 25 / 27 / 32 / 34 / 37 位。

**假设：改用 PG 分语言 tsvector + `ts_rank_cd`，靠 `english` 配置自带的停用词表与
Snowball 词干还原修掉英文失明，同时中文用 bigram 列保持不退化。**

预注册的证伪条件：如果中文题的 Recall 或 MRR 下降，则该方案不能直接换默认。

## 结论

**假设对了一半，被证伪的那一半更有价值。**

- 分语言 tsvector 是对的，**`ts_rank_cd` 是错的**。cover density 对中文 bigram
  明确有害：core-dev 词法单臂 Recall@10 从 0.6302 掉到 0.5312，
  融合后 MRR **−0.1832（CI [−0.3281, −0.0321]，显著）**、
  nDCG **−0.1144（CI [−0.2220, −0.0046]，显著）**。
- 换成 **`ts_rank`（纯词频、不看词间距离）后同一套 tsvector 变成大幅正收益**：
  词法单臂 core **0.6302 → 0.8646**、留出集 **0.0625 → 0.6250**，
  两个数据集都显著，且 **24 条样本里 0 条变差**。
- 融合后的收益方向一致但不显著（core +0.0156、留出 +0.1250，CI 都跨 0）——
  dense 本来就兜住了大部分，这是词法臂改进被稀释的正常表现，不是反证。
- **本次评测测不到英文收益**：`core-dev` / `multihop-test-v1` / `dense-title-smoke`
  三个数据集 **49 条题全部含中文，0 条纯英文**，而语料里 20 篇 PDF 全是英文论文。
  上面那条 PagedAttention 失效样本在标注集里没有对应物。
  → [E3](2026-08-14-E3-英文标注集.md) 补了 20 条纯英文题后测到了：词法单臂 **+0.2188（CI [+0.0625, +0.4375]，显著）**，但融合后 Δ 恰为 0。

原始资料只读，全程本地 Postgres，无远端调用。逐样本内容只留在 Git 忽略的本地报告。

## 实现

迁移 `20260814_0009`：

- 两个 IMMUTABLE 函数：`lexical_zh_bigrams(text)` 把 CJK 连续段切成相邻双字；
  `lexical_en_text(text)` 剥掉 CJK（否则中文段在 `english` 配置下整段变成一个 token，
  既匹配不上英文查询，又会撑宽英文词之间的 cover）。
- `chunks.tsv_en`（`english` 配置）、`chunks.tsv_zh`（bigram + `simple` 配置），
  各自一个 `WHERE is_searchable` 的部分 GIN 索引。
  自 0001 起就存在但从未写入过的 `tsv` 列一并删掉。
- `title` / `heading_path` / `content` 分别 `setweight` 到 A / B / D。
  查询侧当前用平权 `{1,1,1,1}`，与被替换的覆盖率打分同口径（保持单变量）。
  **权重存在列里而不是查询里**，以后调权重不必重建索引。

查询侧两个非默认选择，都是被迫的：

1. **tsquery 用 OR 不用 AND。** `plainto_tsquery` / `websearch_to_tsquery` 都是词间 AND，
   等于要求 chunk 命中查询里每一个词，召回会塌。改成把查询过一遍同配置的
   `to_tsvector`（顺带白拿停用词过滤与词干还原），再把 lexeme 用 `|` 串起来。
2. **两语言分数相加前先归一化。** 两列词表不同，原始 `ts_rank` 不可比；
   用归一化选项 32（`rank/(rank+1)`）压到 [0,1) 再相加。

`title` 在 `documents` 上、跨表，所以做不成 generated column：写入路径
（`document_ingestion`）与迁移回填必须各写一遍同样的表达式。
为此加了一条测试，直接在库里比对存量 tsvector 与重算结果是否逐行相同，
防止两条路径悄悄分叉。

**没有引入 zhparser**：`pgvector/pgvector:0.8.6-pg17-bookworm` 不带该扩展，
装它要自建镜像（SCWS + 编译）。bigram 是零依赖替代，且把「换分词器」留成了
独立变量，不与本次的「换排序函数」混在一起。

## 归因

**为什么 cover density 对中文 bigram 有害。** 离线单臂对照，同一套 tsvector 只换排序函数，
统计 core-dev 16 条可答题里 gold chunk 的名次：

| 打分 | gold 进 Top-10 | gold 进 Top-50 | 平均倒数名次 |
|---|---:|---:|---:|
| coverage | 12 / 16 | 15 / 16 | 0.4202 |
| ts_rank_cd | 9 / 16 | 14 / 16 | 0.4329 |
| **ts_rank** | **15 / 16** | **16 / 16** | **0.7223** |

一句中文自然语言查询会切出十几个 bigram，其中「需要 / 要掌 / 掌握 / 哪些」这类到处都有。
`ts_rank_cd` 奖励「被匹配的 lexeme 挨得紧」，于是它会在任意一篇文档里找到这些高频 bigram 的
紧凑覆盖并给高分，反过来惩罚主题 bigram 分散在整个 chunk 里的正确结果。
`ts_rank` 按词频累加、不看距离，正合中文 bigram 的需要。

**cover density 本身没错，错在配的分词。** 它是为「词元 = 词」设计的；
bigram 把一个词拆成多个位置相邻的 token，位置信息的语义已经变了。
这条恰好说明 zhparser 值得单独试——真正的中文分词下 cover density 可能重新有意义。

**英文侧的修复是真的，但本次测不到。** `english` 配置把 `how/does/in/the` 全部丢掉，
`embeddings → embed`、`retrieval → retriev`，并且是词元匹配不是子串匹配，
`ai` 不会再命中 `said`。同一条查询在 `ts_rank` 下 Top-6 **全部**包含 `pagedattention`
（原来是 0 条）。但三个标注集 49 条题全是中文，**这个收益一条都没进上面的表**。
换句话说，表里的数字是 ts_rank 收益的**下界**。

**顺带订正一条对 D3 的解读。** D3 记的「RRF 带来 +12.5pt」是在全中文题集上测的，
不能据此认为词法臂对英文查询也在起作用——实测它对英文自然语言查询完全失明。
D3 的数字本身没错，外推到英文是错的。

## 决策

1. **`LEXICAL_MODE` 默认从 `coverage` 换成 `ts_rank`。** 依据是被改动部件的直接测量：
   两个数据集都显著，24 条样本 0 条变差。融合 CI 跨 0 属于样本量不足（n=16/8）
   与 dense 稀释，方向在两个数据集上都为正，且英文收益未计入。
   风险可控：单个环境变量即可回滚。延迟顺带从 220ms 降到 11ms，不构成新的取舍。
2. **`ts_rank_cd` 保留为可选档但不使用**，作为可复现的反例留在代码里。
   它的注释直接写明为什么对 bigram 有害。
3. **不引入 zhparser**，理由是保持单变量、避免自建 Postgres 镜像。另开 E4 单独试。
4. **新增 E3（阻塞英文结论）**：标注集必须补纯英文题。
   现在 40 篇语料里 20 篇是英文论文，却没有一条英文题，
   任何关于英文检索的改动都无法被门禁挡住。这是标注覆盖的缺口，不是代码问题。
   → 已完成，见 [E3](2026-08-14-E3-英文标注集.md)：英文收益证实显著，
   但**融合后为零**，这条决策因此有了新的限定，详见 E3。
5. **新增待办**：`ts_rank` 仍然没有 IDF。停用词表覆盖不到的语料高频词
   （`agent` / `model` / `memory`）依然与判别词同权。这才是接 BM25 的确切理由，
   优先级排在英文标注之后。
6. 权重数组保持平权 `{1,1,1,1}`。`setweight` 结构已经存进列里，
   调权重不必重建索引，留作独立变量（与 D7 暴露的 title 加成问题一并考虑）。

## 环境与口径

- 语料：40 篇（21 PDF / 19 Markdown），1862 个可检索 chunk，与 D6 / D7 相同。
- 三档只切换 `--lexical-mode` 这一个变量；dataset、Top-K、diagnostic-K、
  token budget、embedding identity、gold span、RRF k 全部固定。
- 数据集：`core-dev`（20 条人工题，16 可答）、`multihop-test-v1`（8 条留出）。
- Postgres 17 + pgvector 0.8.6，`english` 与 `simple` 均为 PG 内置配置。
