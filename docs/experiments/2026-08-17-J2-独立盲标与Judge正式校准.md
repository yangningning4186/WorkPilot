## 0. 为什么要重做 19 条

J1 的 70 条所谓“人工标签”实际是**助手起草、作者确认**。它足够做工程预检和判者间
一致性，但助手与 Judge 同为大模型，不能回答“Judge 判得准不准”。本轮只重做未参与
rubric 调整的 validation 19 条，并执行以下隔离：

- 盲标包只含冻结 rubric、问题、参考答案和实际答案；
- 不含旧标签、自动指标、heavy/main 预测或分歧信息；
- 19 条按固定 seed `20260817` 重排；
- 作者先独立填写 19 个 0/1 分数，分布为 **0:5 / 1:14**；
- 作者未填写理由。助手在分数 SHA-256 锁定后补写可审计理由，补写前后分数摘要均为
  `eeacfb9b975406c1d1facf2a621ab260c9d5c5ee0fa04631c42915ba5e2b72e1`，没有改分。

因此本轮能诚实声明的是：**分数为作者独立盲标；理由是分数锁定后的助手补写**。
不能把理由也说成独立人工产物。

## 1. 运行中发现并修复的门禁 bug

首轮校准里，两档点估计都超过门槛，却都被 `qwk_bootstrap_incomplete` 判失败：

- heavy 的 10,000 次抽样有 8 次只抽到单一标签；
- main 有 30 次只抽到单一标签。

单一标签时 accuracy 有定义，但 Kappa 的 chance-agreement 分母为 0，QWK 数学上不可定义。
旧实现一边丢弃这些合法退化样本，一边又要求 `effective_resamples == 10000`，所以只要发生
一次退化抽样就必然失败。validation 只有 19 条、少数类 5 条时，这本来就是预期事件，
不是模型或数据损坏。

修复后仍保持 paired percentile bootstrap：退化样本整对丢弃，用同一固定 RNG 确定性补抽，
直到 accuracy/QWK 同时获得 10,000 个有效样本；报告记录总尝试数和丢弃数。原始标签常量或
10 倍尝试仍凑不齐时继续 fail-closed。新增了与真实 validation 同形状（19 条、少数类 5 条）
的回归测试。

### 唯一 validation 分歧

分歧是 `global` 类的“Skill 和 Memory 的边界”：作者判 1，heavy 判 0。实际答案准确给出
“Memory 存事实、Skill 存手册/流程”并判断说法一致；heavy 认为它没有展开 gold 中
TencentDB Agent Memory 的资产视角，因此遗漏了“有哪几种说法”的一个必要要点。

这条不在看过 Judge 后重新裁定，也不用于修改已冻结 rubric。它说明“概括核心边界是否足以
覆盖多个来源视角”仍有解释空间；n=2 的 global validation 也不足以形成类别可靠性结论。

## 3. 决策

1. **六类 `answer-correctness-binary.v2` 中间校准通过。** heavy 和 main 都超过预注册的
   validation 点估计门槛 0.85。
2. **日常/夜间 correctness Judge 采用 main，且显式关闭思考链。** 它在独立 validation 上
   19/19，与 J1 的 2.8× 输出 token、8.3× 墙钟优势方向一致。
3. **heavy 保留为里程碑复核与争议样本对照。** 它同样通过，但 validation 有 1 条偏严格分歧。
4. 结论只覆盖 binary answer correctness 和当前六类，**不能外推**到 faithfulness、
   citation accuracy、三档 rubric 或 `agent_task`。

### 统计边界

- heavy 的 QWK 点估计过门，但 95% CI 下界只有 0.5674；样本量仍不足以证明总体 QWK
  稳定高于 0.85。
- main 的 19/19 只能说明本 validation 未观察到错误，不能读成真实总体准确率必然为 100%。
- 除 single_hop 有 5 条外，其余 validation 类别只有 2–4 条；类别切片继续只报告、不设门禁。
