## 2. 三个必须准备好的叙事

### 2.1 为什么做个人向（对着企业向 JD）

这是**必被问**的问题，也是可以变成加分项的问题。核心逻辑：
不是能力妥协，是为了保住项目最核心的部分。

> "我知道岗位是企业向的。我选个人场景，是因为评测闭环是这个项目的核心——
> 而闭环需要真实用户和真实标注。用合成企业数据，我可以做得表面上更像企业产品，
> 但评测集的 gold answer 就是模型出题模型答，badcase 也是编的，
> 最关键的部分反而是假的。
>
> 技术栈是完全一样的：RAG、Agent、记忆、评测、成本治理。
> 差别只在权限和多租户，这两点我在架构文档里写清楚了要改什么——
> ACL 要下沉到 chunk 做检索前过滤，不能检索后过滤，否则 top-k 会被无权文档占满；
> 真正的难点是连接器的权限同步，源系统的 ACL 要跟着文档一起进来。"

详见 [ADR-0004](adr/0004-面向个人而非企业团队.md)。

### 2.2 一个真实的负优化案例 ★ 加分最多

**必须准备。** 从 `docs/experiments/` 里挑一个假设被推翻的实验，讲清楚：
当时的假设 → 实际结果 → 归因 → 后续决策。

这题答得好，能同时证明：真的跑了实验、会归因、不粉饰结果、有工程判断力。

### 2.3 AI 编程工具的使用方法论

两份 JD 明确要求。不要说"我用 Cursor 写代码"，要说方法论：

> "我把工作分成两类。前端页面、解析流水线、部署配置、测试用例整块交给 agent，
> 我只审边界情况——AI 生成的代码最常缺错误态、加载态、空态。
> 检索融合策略、Agent 图结构、记忆冲突消解规则、评测门禁阈值这四块我自己想清楚再让它落地，
> 因为这些是设计决策，不是编码工作。
>
> 仓库里有 CLAUDE.md 写死了十条不可违背的约束，比如所有 LLM 调用必须走网关、
> Agent 状态必须可序列化、副作用工具必须走幂等协议——这样 agent 改代码时不会破坏架构。
> 提交前用 code-review agent 过一遍，拦下来的问题主要是 ___ 类。"

## 3. 必答面试题清单

开发过程中随时回来自查，答不上来的说明那块还没做透。

### RAG
1. 四种分块策略哪个最好？为什么在你的数据上是这个结论？
1b. **你怎么保证四策略比较是公平的？**（两点：标注锚在字符区间不锚 chunk_id；
   每策略独立部分索引，否则 HNSW 过滤会丢候选，退化程度还和各策略 chunk 数相关）
1c. **你说的 BM25 真的是 BM25 吗？**（诚实答：PG 原生是 `ts_rank_cd` cover-density，
   不是 BM25。要真 BM25 得上 pg_textsearch 或 ParadeDB pg_search，差距在 E2 里量化了）
2. 为什么用 RRF 而不是加权求和？（答案：分数量纲不同、归一化引入偏差、RRF 无需调参）
3. rerank 提升了多少？代价多少延迟？值得吗？
4. 怎么保证引用是真的、不是模型编的？
5. 拒答阈值怎么定的？调高会有什么代价？
6. 全局性问题（"我最近在关注什么"）为什么向量检索答不好？你怎么解决？

### Agent
7. Agent 死循环怎么办？预算上限怎么设？
8. 长任务执行到第 5 步失败，怎么不从头再来？
   （完整答案 = checkpoint 恢复状态 + `tool_invocations` 保证副作用不重放 +
   `agent_attempts` 记录每次尝试。只说 checkpoint 是答不完整的）
8b. **LangGraph 从 interrupt 恢复时会发生什么？**
   （从节点开头重跑，interrupt 之前的副作用会重复执行。所以 HITL 保护的写操作
   反而最容易被写两次——这是必须主动讲的一个坑）
9. Reflection 什么时候是负收益？
10. 工具描述怎么写模型才不会选错？
11. 为什么 LangGraph 而不是 AutoGen / CrewAI？

### 记忆
12. 记忆写入冲突（用户改了偏好）怎么处理？为什么不直接覆盖？
13. 四操作分类器判错了会怎样？怎么兜底？
14. 记忆注入有可测量的收益吗？（**如果没有，如实说，这也是有价值的结论**）

### 评测 ★ 深挖区
15. LLM Judge 怎么验证判得准？（说出 **quadratic weighted** Kappa 的数值 + 混淆矩阵）
15b. **为什么用加权 Kappa 而不是普通 Kappa？**（0/1/2 是有序标签，
   把 0 判成 2 和把 1 判成 2 不该同等惩罚）
16. 评测集会不会过拟合？你怎么防？
17. LLM 输出有随机性，你的指标可信吗？（**paired bootstrap 置信区间**；
   跨 0 就写"无显著差异"。只说"跑三次取中位数"不足以支撑显著性结论）
17b. **评测时 fallback 为什么要关？**（否则 config 记的模型与实际执行的不符，
   实验不可复现而且你不知道）
18. 一个改动在 A 类涨、B 类跌，怎么决策？
19. 门禁阈值怎么定的？（先测噪声地板，阈值必须大于噪声，否则误报会让门禁形同虚设）
19b. **CI 为什么不每次跑全量？**（不是因为贵——自建集群 Judge 几乎免费；
   是 GitHub runner 连不到集群。所以 PR 跑纯规则轨 smoke，夜间在本地跑全量 + Judge）
20. 为什么不直接用 Ragas？

### 工程与成本
21. 三档模型怎么分工的？哪个环节对档位最敏感？
22. 自建模型的成本怎么折算的？（**说不清口径的成本数字一问就穿**。
   要点：不能用 latency × GPU 单价——并发下同一段 GPU 时间会被重复计费 N 次；
   按批次 wall time 摊销，并同时报吞吐、并发、利用率）
22b. **项目上线了，安全上做了什么？**（鉴权 + 限流 + **调用前**费用熔断 +
   上传校验 + 解析子进程隔离 + SSRF 防护 + 私人语料与演示语料物理隔离。
   加分细节：SSRF 要防第二次 DNS 解析的 rebinding）
23. 语义缓存怎么防止错误命中？
24. 如果数据量涨 100 倍，架构哪里先崩？
25. 没有你的集群怎么办？

### 前端
26. 流式生成中用户刷新页面会怎样？
27. SSE 断线重连怎么保证不重不丢？
28. Agent 长任务执行中关闭页面，后端还跑吗？

## 5. 诚实清单

面试中一定会被追问细节。以下事项**必须主动说明**，不要等被问出来：

- [ ] 语料规模（多少篇、多少 chunk）以及全部是个人真实资料
- [ ] 如果引入了公开数据集补充规模，说清比例
- [ ] 单用户产品，没有实现权限与多租户（并说清扩展路径）
- [ ] 没有做过真实高并发压测，瓶颈分析是理论的
- [ ] 评测集实际规模，以及样本量对细分类别的统计显著性有限（要说出置信区间宽度）
- [ ] 哪些功能在 Backlog 没实现（照着 `docs/11-MVP边界.md` 说，不含糊）
- [ ] 哪些指标是 LLM Judge 打的、Judge 本身的一致率是多少
- [ ] SFT 试验如果没做完，**一个字都不要写进简历**

> 主动暴露局限，比被追问出来强一百倍。
> 面试官要找的不是完美项目，是知道自己项目边界在哪的人。
