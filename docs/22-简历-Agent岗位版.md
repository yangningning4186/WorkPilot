## A. 主版本（分层写法，已用于生成 PDF）

**WorkPilot｜本地桌面 Agent（日常办公 + 论文阅读）**　github.com/yangningning4186/WorkPilot　`2026年06月 - 2026年08月`

- **技术栈**：Python 3.12、FastAPI、SQLite、MCP、FAISS、Tauri 2、Next.js 16、TypeScript
- **Agent Runtime 层**：多轮工具循环，状态为可 JSON 序列化的纯函数节点，支持断点续跑、运行中插话纠偏、计划模式与逐步人工审批。终止不靠固定轮数：重复工具签名超阈值即阻断，连续两轮全重复强制收尾，另有调用数 / token / 墙钟三维预算与单工具超时。所有模型调用收敛到统一网关，做多供应商、三档路由与显式非传递降级。
- **幂等与恢复层**：幂等做在有副作用的工具边界，按调用参数规范化生成稳定幂等键，配数据库租约与成功结果复用，避免崩溃恢复后重放已完成的写操作。文件写入先比对基线哈希，再备份并原子替换；事件用单调序号，服务端先订阅后补历史，支持刷新与断线重连。
- **工具与扩展层**：工具面按权限和工作模式动态装配，31 个核心工具加按需扩展。技能包分三层覆盖，用目录索引渐进加载，不每轮把全部说明塞进 prompt。MCP 客户端探测后固定工具清单哈希、逐个显式启用，并限制哪些工具能收到本地语料；只读子 Agent 用隔离上下文与独立轮次上限，共享父任务预算。
- **记忆层**：分全局 / 工作区 / 会话三级作用域。会话结束后异步两阶段抽取，先提候选事实，再对照已有记忆判定新增 / 更新 / 删除 / 忽略，写入与任务状态同事务提交。用时序有效性代替覆盖写：生效时间取源事件时间，旧记录只失效不删除，迟到任务只补历史、不污染当前偏好。
- **检索与阅读接地层**：混合检索用归一化向量的精确 cosine 加 BM25，RRF 融合，可选 cross-encoder 精排；索引按 embedding 签名版本化，签名不符直接拒绝检索而非静默降级。挂载知识库时在 run 起始做一次**确定性预检索**，不经模型决策把命中折进稳定前缀，既提高 prompt 缓存命中，也修掉弱模型整轮不调检索、凭印象作答的问题。阅读侧按 PDF 物理页定位，只有真正读过的原文才登记为可引用证据，检索摘要不算已读；引用逐条核对原文，对不上先修一次，仍失败则拒答。
- **评测与回放层**：版本化用例集与三态回归门禁，支持事件回放、离线重评分和不打真实模型的录制回放；badcase 除进回归集外还要固化成单测。本地通过 881 个后端测试与 42 个端到端用例。

> 写法约束：只用通用术语（幂等键、租约、RRF、cross-encoder、prompt 缓存），项目内部命名
> （evidence ledger / locator / capability / data_scope / cassette）一律翻成人话。
> 桌面化（Tauri sidecar、单实例锁、本地端口 token）与成本记账口径不写进简历，留作口头答。

## D. 面试官最可能下钻的六个点

1. **为什么幂等要放在工具边界，而不是用 step 序号去重？**
   → 恢复的是状态不是副作用；interrupt / 崩溃会重进未确认片段，序号会判成"已执行"。
2. **记忆为什么不是 upsert，而是"不覆盖只失效"？**
   → valid_from 取源事件时间，迟到的旧任务只能写历史，不会盖掉更晚的当前偏好；
   审计与回滚也需要看得见改写链（superseded_by）。顺带：pin 记忆禁止自动改写。
3. **记忆工具为什么不走调用租约？**
   → 它们是 control-plane 操作、effect=none，复用面向外部系统的租约只会加协议复杂度；
   代价是数据库写入自身必须事务化且可重试。
4. **三维预算里哪一维最先触发？** → 通常是重复工具签名熔断先于预算；预算是兜底。
5. **子 Agent 为什么只读？** → 可写多 Agent 的冲突消解与幂等成本远大于收益，当前是明确的非目标。
6. **evaluation 怎么保证可复现？** → 评测模式强制关闭 fallback + fixture cassette 零真实调用 +
   版本化 catalog/policy；PR 门禁不跑评测，badcase 必须同时固化成 pytest 用例。

## F. 不能用的数字

- **87.5% Agent 成功率**：旧 40-case synthetic 快照，新 50-case suite 尚无冻结结果。
- **95.45% 引用准确率**：退役 PostgreSQL 架构的人审历史集。
- **混合检索 +3.92pt nDCG**：置信区间跨 0。
- 可用但需说明口径：BGE reranker 在 22 条待人工复核的 dev query 上把 nDCG@5 从 61.63% 提到
  81.05%（+19.42pt，95% paired-bootstrap CI [+4.22,+34.39]），代价约 +655ms；因同一 dev 集
  参与调参且无 holdout，最终选择可选、fail-open、默认关闭。
