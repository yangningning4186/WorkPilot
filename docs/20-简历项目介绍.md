## 1. 推荐主版本

### WorkPilot｜本地桌面 AI 助手（日常办公 + 论文阅读）

`[个人项目 / 你的实际角色]`　`[起止时间]`　`[GitHub / Demo 链接]`

面向研究者、工程师和知识工作者的本地桌面 AI Agent，以**日常办公**和**论文阅读**为两个并列主场景：既能安全处理文件、Office 与自动化任务，也能按页精读论文、跨论文检索并验证引用；两条主线共用同一个可恢复 run，并可直接把论文证据转化为周报、表格或演示文稿。

- 基于 **Tauri 2 + Next.js 16 + FastAPI** 构建本地桌面运行底座，以 SQLite、JSONL 和版本目录持久化 run、事件、对话与知识索引；通过启动级 token、单实例锁、健康探针和 SSE 回放支持安全启动、断线恢复与应用重启续跑。
- **日常办公：**支持 Markdown / DOCX / XLSX / PPTX / PDF、文件、网页、Git、受控 Shell、Artifact 和单次 / cron 自动化；用目录授权、baseline hash、冲突检测、备份、重新打开校验、原子替换及语义 diff 保障真实文件操作。
- **论文阅读：**实现 PDF 物理页 / block bbox 精读、引用跳页高亮与持久批注，只有实际 read 的内容才能进入 evidence ledger；跨论文知识库采用版本化 **FAISS IndexFlatIP + BM25 + RRF**，支持 embedding signature、原子发布与可选精排。
- 构建两条主线共享的自研确定性 Agent 工具循环：checkpoint 负责状态恢复，稳定 invocation identity + lease 负责副作用去重，并叠加 capability、资源 scope、HITL、计划模式、三维预算和重复调用熔断。
- 建立版本化 suite、隐私最小化 baseline、policy 和 0 / 1 / 2 三态回归门禁，支持事件回放、observation 离线重评分和零真实模型 dispatch 的 fixture cassette；2026-08-24 本地验证通过 **881 个后端测试、42 个 Playwright E2E 和 5 个 reranker 测试**。

**技术栈：** Python 3.12、FastAPI、Pydantic、SQLite、JSONL、LlamaIndex、FAISS、BM25、Tauri 2、Rust、Next.js 16、React 19、TypeScript、Playwright、PyMuPDF

> “日常办公”和“论文阅读”两条必须同时保留，才能表达真实产品定位；篇幅不足时，从平台、Agent 可靠性、评测三条中按岗位删减。测试数字的口径是 2026-08-24 本地验证：Playwright 使用 mock backend，远端 CI 与生产全链路尚未验证，所以不要扩大结论边界。

## 3. 按岗位选择的版本

### 3.1 AI Agent / 应用算法岗

**WorkPilot｜日常办公与论文阅读一体化 Agent**　`[角色｜时间｜链接]`

- 以日常办公和论文阅读为并列工作模式：办公模式组合文件、Office、Shell、网页与自动化，阅读模式组合 locator、evidence、Reader 与知识检索；两侧共用同一个状态、权限和工具循环。
- 设计可恢复的 Agent 决策—工具循环：状态 JSON 化、checkpoint、HITL、运行中 steering、上下文压缩和三维预算；对重复工具签名与连续空转设置协议级熔断。
- 将幂等下沉到副作用工具边界，以 `run + step + tool + canonical args` 生成稳定 identity，结合数据库 lease 和成功结果复用，避免 checkpoint / interrupt 重放导致重复写操作。
- 按工作模式和 capability 动态构建工具面，支持 31 个核心工具及 Skill / MCP 扩展；只读子 Agent 使用隔离上下文、只读 registry、独立轮次 / 工具上限并共享父任务总预算。
- 将稳定 system / tool / persona / memory 前缀与动态会话状态分离，提高 provider prompt cache 可复用性；统一网关支持多供应商、显式非传递 fallback、调用前费用预留和精确 completion cache。

### 3.2 RAG / 搜索算法岗

**WorkPilot｜可溯源个人知识库与沉浸阅读**　`[角色｜时间｜链接]`

- 实现“单篇精读 + 跨文档检索”双通路：精读按 PDF 物理页 / 文本章节定位并回传 bbox，只有实际 read 的内容可进入 evidence ledger；模型引用可驱动阅读器跳页、高亮和持久批注。
- 构建版本化文件系统知识库：内容寻址 source snapshot、embedding model / dimensions / revision 签名、staging 构建、原子 manifest 发布和显式 active，避免失败构建或向量签名漂移污染在线索引。
- 使用归一化向量上的 FAISS IndexFlatIP 实现精确 cosine 检索，结合真 BM25 与 RRF 融合；可选 BGE cross-encoder 精排，具备超时、返回协议校验和 fail-open 降级。
- 建立 Recall、nDCG、MRR、引用、拒答和阅读定位指标，使用 10,000 次 paired bootstrap 报告差值置信区间；对 CI 跨 0 的混合检索实验不做显著提升声明。

### 3.3 Python 后端 / 平台岗

**WorkPilot｜本地优先 Agent 运行平台**　`[角色｜时间｜链接]`

- 基于 FastAPI + SQLite WAL 构建本机持久任务系统：run 初始化 / 排队 / claim / lease / watchdog / recovery 状态机，进程内队列仅作唤醒，SQLite queued 状态作为 durable truth。
- 将长对话正文设计为 append-only JSONL，SQLite 保存 byte offset / length 索引；业务事件使用原子单调 seq，服务端“先订阅、后补历史”关闭 SSE 建连竞态。
- 设计 tool invocation lease、resume token、文件 baseline hash、原子替换和 schedule dispatch lease，覆盖崩溃恢复、重复确认、用户并发编辑与无人值守补跑等一致性问题。
- 使用 import-linter 强制模块单向依赖，统一模型网关和成本 telemetry；本地审计中 881 个后端测试、mypy 211 个 source file 与 8 条架构 contract 通过。

### 3.4 全栈 / 桌面应用岗

**WorkPilot｜桌面 AI 办公与论文阅读工作台**　`[角色｜时间｜链接]`

- 使用 Tauri 2 管理 FastAPI sidecar：安全随机 token、loopback 动态端口、ready 探测、进程组退出、打包态固定 sidecar 和数据目录单实例锁；Next.js 16 静态导出为桌面 UI。
- 设计基于持久事件的 React 状态层，实时 SSE 与历史 replay 复用纯 reducer，按 run 隔离 AbortController / cursor；覆盖刷新恢复、断线重连、重复事件去重和并行会话。
- 实现日常办公侧的 Cowork / Artifact / Automations / Connectors，以及论文阅读侧的 Reader / Knowledge；支持 PDF canvas + selectable text layer、引用跳转高亮、Office 预览与 semantic diff。
- Playwright 覆盖 Markdown / 引用安全、SSE 恢复、并行 run、Reader、Memory、Connector 和 Provider 等 42 个场景；TypeScript、ESLint、桌面静态构建与 Rust `cargo check` 通过。

### 3.5 安全工程侧重版

**WorkPilot｜受控执行的本地 AI Agent**　`[角色｜时间｜链接]`

- 将模型“能看见工具”、用户“授权资源范围”和单次“人工批准”拆成 capability、permission scope、approval 三层，所有副作用在后端重新验证，不信任前端或 prompt 声明。
- 文件操作执行 canonical path / symlink escape 检查、读取 baseline hash、并发冲突检测、备份与原子替换；Shell 对运算符命令永不免审，容器沙箱禁网、只读 rootfs、drop capabilities 且不回退宿主机。
- 网页读取对协议、userinfo、IDNA 和 global IP 做校验，固定已审计 DNS IP，保留原 Host / SNI，并对每次重定向重新授权，防止 DNS rebinding 与内网探测。
- MCP 采用 catalog hash 固定、逐工具策展、语料出站 scope 与 external side-effect capability；OAuth token 使用独立主密钥的 Fernet 私密存储并以原子文件写入。

## 4. 可选的实验数字版

只有面试官明确重视实验，且简历有空间说明口径时再使用：

> 在 22 条可答、待人工复核的文件系统 KB dev query 上，可选 BGE reranker 将 nDCG@5 从 61.63% 提至 81.05%（+19.42pt，95% paired-bootstrap CI [+4.22,+34.39]），MRR 从 52.80% 提至 78.03%（+25.23pt，CI [+7.14,+43.17]），平均增加约 655ms；因同一 dev 集参与调参且缺少 holdout，最终采用可选、fail-open、默认关闭策略。

这个版本的价值不是数字大，而是能同时展示：

- 你会报告 CI，而不只报点估计；
- 你量化了延迟代价；
- 你知道 dev / holdout 泄漏风险；
- 你会根据产品分发成本做“暂不默认启用”的决定。

不建议使用这些数字：

- **87.5% Agent 成功率**：来自旧 40-case synthetic 快照，新的 50-case suite 尚无冻结结果。
- **95.45% 引用准确率**：来自退役 PostgreSQL 架构的人审历史集，不代表当前 filesystem KB。
- **混合检索 +3.92pt nDCG**：置信区间跨 0，不能写“显著提升”。
- **记忆提升质量**：A6 总门禁失败。

## 7. 不要这样写

| 不推荐表述 | 问题 | 建议改写 |
|---|---|---|
| “个人知识库 / RAG 项目” | 把日常办公主线完全隐藏 | 开场明确“日常办公 + 论文阅读”，再分别给出能力和融合场景 |

| “实现三层记忆和知识图谱” | 知识图谱未实现 | 写 global / workspace / conversation 时序记忆 |
| “使用 HNSW 向量检索” | 当前代码不是 HNSW | 写归一化 FAISS IndexFlatIP 精确 cosine |
| “保证 exactly-once” | 外部系统存在不确定提交窗口 | 写协议内 effectively-once 与幂等 key 边界 |
| “生产级安全” | 发布链、限流、多租户未完成 | 列举具体控制和剩余风险 |

| “已上线并真实使用” | 需要你提供外部证据 | 只在确有链接、日志或用户记录时写 |

## 8. 面试开场建议

简历写得越满，面试官越容易从任意一条下钻。推荐把主版本压到四条，并确保每条都能回答：

无论压缩到几条，**日常办公**和**论文阅读**各自至少保留一条；共享 Agent 底座、评测或安全能力按岗位取舍。开场先分别举一个独立场景，再用“论文结论直接进入周报 / Excel / PPT”说明两条主线为什么值得放在同一产品里。

1. 当时的具体问题是什么？
2. 为什么没选更常见的替代方案？
3. 最危险的边界条件是什么？
4. 测试或实验如何验证？
5. 方案还剩什么风险？

完整答案、架构图、实验口径和追问题库见 [`19-项目全景与面试作战手册.md`](19-项目全景与面试作战手册.md)。
