# WorkPilot 本地启动指南

本文面向 macOS 本地开发环境。完成一次初始化后，日常只需要执行一条命令即可启动
WorkPilot 桌面客户端。

## 1. 启动方式速查

先把仓库绝对路径保存为任务专用变量；下文命令都复用它：

```bash
WORKPILOT_ROOT=/absolute/path/to/workpilot
```

如果依赖已经安装完成：

```bash
cd "$WORKPILOT_ROOT/frontend"
npm run dev:desktop
```

看到桌面窗口，并且终端出现以下日志，就表示完整启动成功：

```text
✓ Ready
Application startup complete.
GET /health/ready HTTP/1.1" 200 OK
[desktop] desktop_context: ready
```

这个命令会自动启动完整开发链：

1. Next.js 前端，固定使用 `http://127.0.0.1:3000`；
2. Tauri 桌面窗口；
3. FastAPI sidecar，端口每次随机选择；
4. 本机嵌入式 Cowork worker。

不需要另外启动 PostgreSQL、Redis、Docker 或后端进程。

> 不要用 `npm run dev` 代替。它只启动网页前端，不会启动 Tauri、FastAPI sidecar 和
> 嵌入式 worker，无法完整测试 Cowork 桌面能力。

## 2. 首次初始化

### 2.1 环境要求

先确认本机具备：

- macOS 的 Xcode Command Line Tools；
- Python 3.12；
- `uv`；
- Node.js 20 或更高版本，以及 npm；
- Rust stable 工具链（包含 `cargo`）。

可以用下面的命令检查：

```bash
xcode-select -p
python3 --version
uv --version
node --version
npm --version
rustc --version
cargo --version
```

### 2.2 安装后端依赖

桌面壳会直接调用 `backend/.venv/bin/python`，所以首次运行前必须生成这个虚拟环境：

```bash
cd "$WORKPILOT_ROOT/backend"
uv sync --locked
```

### 2.3 安装前端依赖

```bash
cd "$WORKPILOT_ROOT/frontend"
npm ci
```

完成后执行：

```bash
npm run dev:desktop
```

首次启动可能需要编译 Rust 依赖，会比后续启动慢。

## 3. 日常启动与退出

### 启动

打开终端执行：

```bash
cd "$WORKPILOT_ROOT/frontend"
npm run dev:desktop
```

保持这个终端窗口运行。开发模式会监听前端和 Tauri 代码变化；普通前端修改通常会自动刷新。
修改 Python 后端启动逻辑后，建议完整退出再重新执行启动命令。

### 退出

回到运行启动命令的终端，按：

```text
Control + C
```

这样会一起停止桌面客户端、Next.js 和 sidecar。只关闭桌面窗口后，最好确认终端里的开发命令
也已经结束，避免旧 worker 留在后台。

## 4. 拉取新代码后的操作

如果依赖锁文件没有变化，通常直接重新启动即可。如果 `backend/uv.lock`、
`frontend/package-lock.json` 或 Rust 依赖发生变化，重新同步：

```bash
cd "$WORKPILOT_ROOT/backend"
uv sync --locked
```

```bash
cd "$WORKPILOT_ROOT/frontend"
npm ci
npm run dev:desktop
```

## 5. 构建原生安装包

发布构建会把 Python 后端和受控浏览器一起放进 Tauri 包，安装后的应用不再读取仓库里的
`backend/.venv`，也不接受 `WORKPILOT_SIDECAR` 之类的外部可执行文件覆盖：

```bash
cd "$WORKPILOT_ROOT/backend"
uv sync --locked
uv run playwright install chromium

cd "$WORKPILOT_ROOT/frontend"
npm ci
npm run bundle:desktop
```

`package:sidecar` 会先生成目标三元组命名的 sidecar，随后在临时数据目录里执行迁移和完整 API
健康检查；烟测不通过就不会继续打包。构建清单记录 sidecar 的 SHA-256、尺寸、Python 版本和
浏览器运行时版本。Tauri 最终产物位于：

```text
frontend/src-tauri/target/release/bundle/
```

这条链路只支持原生构建，不能在 macOS 上生成 Windows/Linux 的 Python sidecar。对外分发前，
还必须配置各平台的正式代码签名；macOS 还需要 Developer ID 签名、公证与 stapling。本地 ad-hoc
签名或能双击启动的 DMG 不能替代发布签名。

## 6. 本地数据位置

应用状态默认保存在：

```text
~/.workpilot/
```

其中包括 SQLite 控制面、会话 JSONL、知识库索引和遥测数据。普通任务的新交付物默认写到：

```text
~/Documents/WorkPilot/
```

升级时数据库迁移会自动执行。遇到启动错误时不要先删除 `~/.workpilot`，否则会丢失会话、
授权和本地配置；应先保留日志并排查迁移问题。需要人工处理数据前，可以先备份：

```bash
cp -a ~/.workpilot ~/.workpilot-backup
```

## 7. 常见问题

### 7.1 `backend/.venv/bin/python` 不存在

后端依赖尚未初始化，执行：

```bash
cd "$WORKPILOT_ROOT/backend"
uv sync --locked
```

### 7.2 `node_modules` 或 Tauri CLI 不存在

执行：

```bash
cd "$WORKPILOT_ROOT/frontend"
npm ci
```

### 7.3 端口 3000 被占用

先查看占用进程：

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN
```

确认它确实是旧的 WorkPilot/Next 进程后，对准确 PID 发送正常退出信号：

```bash
kill -TERM <PID>
```

不要在未确认进程归属时批量 `pkill node`，这会误伤其他前端项目和编辑器插件。

### 7.4 sidecar 未就绪

重点查看启动终端中 `Started server process` 后面的 Python traceback。正常启动一定会出现：

```text
GET /health/ready HTTP/1.1" 200 OK
[desktop] sidecar readiness passed
```

如果没有出现，先按 `Control + C` 完整退出，再重新运行 `npm run dev:desktop`。仍失败时保留
从 `Waiting for application startup` 开始的全部日志，不要删除本地数据库。

### 7.5 如何确认是否有旧进程残留

```bash
ps -axo pid=,ppid=,command= | rg "$WORKPILOT_ROOT|workpilot-desktop|tauri\\.js dev"
```

正常退出后不应再看到 `workpilot-desktop`、`tauri.js dev` 或项目目录下的 sidecar 进程。

### 7.6 看到 `cost_sweeper_tick` 维护告警

如果 `/health/ready` 已返回 200 且主要接口正常，这类后台费用维护告警不会阻塞 Cowork 的
基础功能测试；需要测试成本统计或费用闸门时再单独排查。

## 8. 启动问题反馈清单

反馈启动故障时，最好一并提供：

- 执行的启动命令；
- 从 `npm run dev:desktop` 开始到报错结束的终端日志；
- `node --version`、`uv --version`、`rustc --version`；
- 是否出现 `/health/ready 200 OK`；
- 最近是否修改依赖锁文件或 `~/.workpilot` 数据。
