# 03 · 数据模型

PostgreSQL 17 + pgvector。主键 UUID v7（时间有序，索引局部性好）。

**单用户产品**：不引入 `workspace_id` 和语料 ACL。公网 demo 仍需按匿名 session 隔离
对话/run；这是访问边界，不是多租户知识权限。多用户扩展点见 [02 §7](02-架构设计.md)。

> **2026-08-13 重构**：修复三处结构性缺陷 —— 评测标注与分块策略耦合、
> Agent 幂等模型不成立、SSE 续传缺持久化事件源。
> 决策记录见 [ADR-0006](adr/0006-分块与标注分层.md)、[ADR-0007](adr/0007-agent幂等与事件溯源.md)。

## 0. 分层总览

知识层的核心是**四层分离**，这是整个数据模型最重要的设计：

```
documents            逻辑文档（跨版本稳定的身份）
  └─ document_versions   内容版本（每次变更一版，带 full_text 作为字符偏移基准）
       └─ parsed_blocks      ★ 解析产出的稳定最小单元 —— 标注与溯源的锚点
            └─ chunks            某个分块策略下的产物，可有多套并存
```

**为什么必须分这四层**：
评测的 gold 标注锚定在 `parsed_blocks` 的字符区间上，而不是 `chunk_id`。
于是同一份标注可以给任意分块策略打分——四策略对照实验才成立，
重新分块也不会作废标注。这是 [ADR-0006](adr/0006-分块与标注分层.md) 的核心。

## 1. 数据源

> 借鉴 Onyx 的连接器抽象：资料由 connector 周期性同步，而非一次性上传。
> 笔记库会持续修改，增量同步是唯一正确的做法。

```sql
CREATE TABLE sources (
    id           UUID PRIMARY KEY,
    kind         TEXT NOT NULL
        CHECK (kind IN ('local_dir','obsidian','zotero','web_clip','upload')),
    name         TEXT NOT NULL,
    config       JSONB NOT NULL,       -- {root, include_globs, exclude_globs, ...}
    sync_cursor  TEXT,                 -- 增量游标（时间戳 / 文件系统快照）
    last_sync_at TIMESTAMPTZ,
    sync_status  TEXT NOT NULL DEFAULT 'idle'
        CHECK (sync_status IN ('idle','syncing','failed')),
    sync_error   TEXT,
    enabled      BOOLEAN NOT NULL DEFAULT true,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

> `local_dir` 的 `config.root` 必须经 realpath 校验限制在允许根目录内，
> `web_clip` 的抓取必须做 SSRF 防护 —— 见 [12 安全与部署](12-安全与部署.md)。

`source_sync_entries` 以 `(source_id, source_uri)` 为主键，持久化 `size_bytes`、`mtime_ns`、
`content_hash`、`ingest_signature`、单文件同步状态与错误。`ingest_signature` 覆盖解析策略/版本、
分块参数与 embedding 身份：只有 stat 和签名都相同时才快速跳过；策略或模型变化会重建版本。
文件消失时软删除对应 `documents` 并关闭其 chunks 的检索可见性。

## 2. 文档与版本

```sql
-- 逻辑文档：身份跨版本稳定
CREATE TABLE documents (
    id             UUID PRIMARY KEY,
    source_id      UUID NOT NULL REFERENCES sources(id) ON DELETE RESTRICT,
    source_uri     TEXT NOT NULL,
    title          TEXT NOT NULL,
    doc_type       TEXT NOT NULL
        CHECK (doc_type IN ('paper','note','book','web','doc','code')),
    tags           TEXT[] NOT NULL DEFAULT '{}',
    -- 个人场景特有：支撑待读积压与 digest
    read_status    TEXT NOT NULL DEFAULT 'unread'
        CHECK (read_status IN ('unread','reading','read')),
    starred        BOOLEAN NOT NULL DEFAULT false,
    added_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_opened_at TIMESTAMPTZ,
    -- 删除语义之一：用户主动删除（见 §9）
    deleted_at     TIMESTAMPTZ,
    meta           JSONB NOT NULL DEFAULT '{}',   -- 作者、年份、arXiv id、来源 URL
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (source_id, source_uri)
);
CREATE INDEX idx_doc_live ON documents (doc_type, added_at) WHERE deleted_at IS NULL;
CREATE INDEX idx_doc_tags ON documents USING GIN (tags);

-- 内容版本：每次内容变化产生一版
CREATE TABLE document_versions (
    id             UUID PRIMARY KEY,
    document_id    UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    version_no     INT  NOT NULL,
    content_hash   TEXT NOT NULL,        -- 未变则跳过重解析
    -- 解析器信息：bbox 坐标的解释依赖它（P1-d）
    parser         TEXT NOT NULL,        -- mineru | docling | markdown | trafilatura
    parser_version TEXT NOT NULL,
    parse_meta     JSONB NOT NULL DEFAULT '{}', -- backend、选择/回退原因、耗时、质量指标
    page_count     INT,
    -- ★ NFC 归一化全文：所有 char_start/char_end 的基准坐标系
    -- pending/parsing 期间可为 NULL，进入 done 时必须填充
    full_text      TEXT,
    -- 时序有效性
    valid_from     TIMESTAMPTZ,          -- 激活成功时才设置，不是开始解析时
    invalid_at     TIMESTAMPTZ,          -- 当前版本还要求 activated_at 非 NULL
    activated_at   TIMESTAMPTZ,
    parse_status   TEXT NOT NULL DEFAULT 'pending'
        CHECK (parse_status IN ('pending','parsing','done','failed','superseded')),
    parse_error    TEXT,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (document_id, version_no),
    CHECK (invalid_at IS NULL OR (valid_from IS NOT NULL AND invalid_at > valid_from)),
    CHECK (activated_at IS NULL OR (parse_status = 'done' AND full_text IS NOT NULL))
);
-- 每个文档至多一个已激活的当前版本。pending/parsing 候选版本可与旧版并存。
CREATE UNIQUE INDEX uq_docver_current
    ON document_versions (document_id)
    WHERE activated_at IS NOT NULL AND invalid_at IS NULL;
```

### 2.1 版本激活协议 ★

新内容不能在解析开始时就替换旧版。正确流程是：

```text
事务锁住逻辑文档；若 hash 与最新且未失效的 `pending/parsing/done` 版本相同则跳过，
否则分配下一 version_no，创建候选版本
（pending，valid_from/activated_at 均为 NULL）
  → parsing
  → 写 full_text / parsed_blocks / chunks / embedding
  → done
  → 一个数据库事务内激活：
       1. SELECT 逻辑文档 FOR UPDATE
       2. 验证候选仍是该文档最大 version_no；否则标 superseded 并退出
       3. 旧活跃版本 invalid_at = now()
       4. 旧 chunks is_searchable = false
       5. 新版本 valid_from = activated_at = now()
       6. 新 chunks is_searchable = true
```

解析失败只把候选版本标为 `failed`，旧活跃版本继续服务。
这避免了“先让旧版失效，新版又解析失败”导致文档短暂不可用。
“只激活最新候选”的守卫还避免了 v2 慢解析、v3 先完成后，v2 晚到反向降级。
`content_hash` 不做跨历史版本唯一约束：文件内容从 A 改成 B 后又恢复为 A，仍需创建
新版本来表达新的有效时间区间；并发去重由创建候选时的文档行锁保证。

## 3. parsed_blocks ★ 标注锚点

**这张表是整个重构的支点。** 它是解析产物的稳定表示，
不随分块策略变化，因此可以承载 gold 标注和引用溯源。

```sql
CREATE TABLE parsed_blocks (
    id           UUID PRIMARY KEY,
    version_id   UUID NOT NULL REFERENCES document_versions(id) ON DELETE CASCADE,
    block_idx    INT  NOT NULL,          -- 阅读顺序（双栏论文已重排序）
    block_type   TEXT NOT NULL
        CHECK (block_type IN ('title','paragraph','table','list',
                              'figure_caption','formula','code')),
    text         TEXT NOT NULL,
    -- ★ 在 NFC full_text 中的 Unicode code-point 区间：标注与映射的基准
    char_start   INT NOT NULL,
    char_end     INT NOT NULL,
    heading_path TEXT[],
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (version_id, block_idx),
    CHECK (char_start >= 0 AND char_end > char_start)
);
CREATE INDEX idx_block_span ON parsed_blocks (version_id, char_start, char_end);

-- 一个块可以跨页或对应多个不连续区域（跨页表格、多栏段落）
CREATE TABLE parsed_block_locations (
    block_id      UUID NOT NULL REFERENCES parsed_blocks(id) ON DELETE CASCADE,
    location_idx  INT  NOT NULL,
    page_no       INT  NOT NULL,
    page_width    REAL NOT NULL,
    page_height   REAL NOT NULL,
    rotation      INT  NOT NULL DEFAULT 0 CHECK (rotation IN (0,90,180,270)),
    coord_origin  TEXT NOT NULL DEFAULT 'top_left'
        CHECK (coord_origin IN ('top_left','bottom_left')),
    bbox_norm     JSONB NOT NULL,          -- [x0,y0,x1,y1] 归一化到 [0,1]
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (block_id, location_idx),
    CHECK (location_idx >= 0 AND page_no >= 1),
    CHECK (page_width > 0 AND page_height > 0)
);
CREATE INDEX idx_block_location_page ON parsed_block_locations (page_no, block_id);
```

**为什么 bbox 要存归一化坐标 + 这一堆元数据**：
PDF 原生坐标系原点在左下角，而绝大多数前端渲染器（pdf.js 等）用左上角；
页面可能带旋转；不同解析器输出的坐标基准不一致。
只存 `[x0,y0,x1,y1]` 四个数，换个渲染器高亮就会错位。
归一化到 `[0,1]` 后，前端按实际渲染尺寸缩放即可。
位置用子表而非 block 上的单个 bbox，否则无法表达跨页表格和多区域高亮。

**offset 口径**：`char_start/end` 统一指 NFC 文本的 Unicode code-point 索引。
浏览器的 Selection API 给出 UTF-16 offset，不得直接入库；
标注 API 必须把 `block_id + 局部 UTF-16 offset + quote` 交给后端，
由后端转成 code-point offset 并校验 quote 后再生成 gold span。

## 4. chunks

```sql
CREATE TABLE chunks (
    id                  UUID NOT NULL,
    version_id          UUID NOT NULL REFERENCES document_versions(id) ON DELETE CASCADE,
    strategy            TEXT NOT NULL
        CHECK (strategy IN ('fixed','recursive','semantic','heading')),
    chunk_index         INT  NOT NULL,
    content             TEXT NOT NULL,
    content_tokens      INT  NOT NULL,
    -- ★ 覆盖范围：既记 block 区间，也记字符区间（block 可能被切开）
    block_start_idx     INT NOT NULL,
    block_end_idx       INT NOT NULL,
    char_start          INT NOT NULL,
    char_end            INT NOT NULL,
    dominant_block_type TEXT NOT NULL,
    heading_path        TEXT[],
    -- 检索索引
    embedding           vector(1024),    -- bge-m3 dense
    sparse              JSONB,           -- bge-m3 sparse：生成即存，v1 不建检索路径（§10）
    tsv                 TSVECTOR,        -- 词法检索（注意：ts_rank_cd，不是 BM25）
    -- 检索前过滤字段（冗余下沉，避免 JOIN 拖慢向量查询）
    doc_type            TEXT NOT NULL,
    tags                TEXT[] NOT NULL DEFAULT '{}',
    -- 统一表达“版本已激活 + 文档未删除”，是检索可见性的唯一开关
    is_searchable       BOOLEAN NOT NULL DEFAULT false,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (id),
    UNIQUE (version_id, strategy, chunk_index),
    CHECK (char_end > char_start),
    CHECK (block_end_idx >= block_start_idx)
);
```

### 4.1 每策略独立的向量索引 ★ P1-c 修复

**错误做法**（重构前）：四种策略共用一个 HNSW，查询时 `WHERE strategy = 'heading'` 过滤。
pgvector 的过滤发生在**候选扫描阶段**——HNSW 扫出的候选中约 75% 会被丢弃，
很可能凑不满 top-k。这不只是性能问题：
**E1 四策略对照测出来的差异会混进索引退化的噪声，结论直接是错的。**

**正确做法**：每策略一个部分索引，查询走各自的索引，无索引内过滤损失。

```sql
CREATE INDEX idx_chunk_vec_heading   ON chunks USING hnsw (embedding vector_cosine_ops)
    WITH (m=16, ef_construction=64) WHERE strategy = 'heading' AND is_searchable;
CREATE INDEX idx_chunk_vec_recursive ON chunks USING hnsw (embedding vector_cosine_ops)
    WITH (m=16, ef_construction=64) WHERE strategy = 'recursive' AND is_searchable;
CREATE INDEX idx_chunk_vec_fixed     ON chunks USING hnsw (embedding vector_cosine_ops)
    WITH (m=16, ef_construction=64) WHERE strategy = 'fixed' AND is_searchable;
CREATE INDEX idx_chunk_vec_semantic  ON chunks USING hnsw (embedding vector_cosine_ops)
    WITH (m=16, ef_construction=64) WHERE strategy = 'semantic' AND is_searchable;

CREATE INDEX idx_chunk_tsv    ON chunks USING GIN (tsv);
CREATE INDEX idx_chunk_filter ON chunks (strategy, doc_type, is_searchable);
CREATE INDEX idx_chunk_ver    ON chunks (version_id, strategy, chunk_index);
CREATE INDEX idx_chunk_span   ON chunks (version_id, strategy, char_start, char_end);
```

当前问答的查询必须显式带 `is_searchable = true`，才能命中上述部分索引。
**剩余过滤条件**（`doc_type` / `tags`）仍在索引内过滤，
用 pgvector 的**迭代扫描**兜底，避免候选不足：

```sql
SET hnsw.iterative_scan = relaxed_order;
SET hnsw.max_scan_tuples = 20000;
```

`chunks.doc_type/tags/is_searchable` 是性能所需的冗余，但不能靠业务代码“记得更新”。
版本激活、用户删除/恢复、源同步删除、`doc_type/tags` 修改都必须走同一个
repository 事务，并有数据库一致性测试验证“文档状态 = chunk 投影”。

历史时间点查询不走当前版本部分索引：先按有效区间解析出有限的 `version_id` 集合，
再在这些版本内做精确向量扫描。历史查询量或归档规模达到瓶颈后，才单独建设归档索引；
不要让大量失效版本污染高频的当前问答 HNSW。

> 若语料规模增长到部分索引维护成本过高，再改为 `PARTITION BY LIST (strategy)`。
> 分区方案更彻底（分区裁剪），但主键必须包含分区键，会牵动引用 chunk_id 的地方。
> 当前规模下部分索引更简单，**简单优先**。

### 4.2 建库顺序

**先灌数据，后建 HNSW 索引。** 反过来构建慢一个数量级。

## 5. 对话层

```sql
CREATE TABLE conversations (
    id           UUID PRIMARY KEY,
    scope        TEXT NOT NULL CHECK (scope IN ('local_owner','demo')),
    demo_session_id UUID,                  -- 来自服务端 session；local_owner 为 NULL
    title        TEXT,
    summary      TEXT,                    -- 工作记忆：滚动压缩的会话摘要
    summary_upto INT NOT NULL DEFAULT 0,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    CHECK ((scope = 'local_owner' AND demo_session_id IS NULL)
        OR (scope = 'demo' AND demo_session_id IS NOT NULL))
);
CREATE INDEX idx_conversation_demo_session
    ON conversations (demo_session_id, updated_at) WHERE scope = 'demo';

CREATE TABLE messages (
    id              UUID PRIMARY KEY,
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    seq             INT  NOT NULL,
    role            TEXT NOT NULL CHECK (role IN ('user','assistant','tool','system')),
    content         TEXT NOT NULL DEFAULT '',
    -- ★ 流式状态：刷新页面后要能区分"生成中"和"已完成"（P0-4）
    status          TEXT NOT NULL DEFAULT 'completed'
        CHECK (status IN ('streaming','completed','failed','cancelled')),
    run_id          UUID,                 -- 关联 run_events，用于续传
    citations       JSONB NOT NULL DEFAULT '[]',
    -- [{citation_id, block_id, version_id, doc_id, title, quote, char_start, char_end,
    --   locations: [{page_no, bbox_norm, page_width, page_height, rotation, coord_origin}]}]
    trace_id        TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (conversation_id, seq)
);
CREATE INDEX idx_msg_run ON messages (run_id) WHERE run_id IS NOT NULL;
```

> **引用锚定在 `block_id` 而非 `chunk_id`**：block 跨策略稳定，
> 换分块策略后，历史消息的引用依然能定位到原文；重新解析会生成新版本，
> 历史引用仍指向原版本，除非执行物理清理。

## 6. Agent 层 ★ P0-3 重构

### 6.1 为什么原设计是错的

重构前用 `agent_steps` 单表 + `UNIQUE (run_id, step_idx)` 宣称实现幂等。三处矛盾：

1. 同一计划步骤会产生 executor、reflector 多条记录 → 唯一约束直接冲突
2. 有 `retry_of` 字段说明允许重试，但重试写新行时 `step_idx` 必然不同 → 约束形同虚设
3. **最要命的**：LangGraph 从 interrupt 恢复时会**从所在节点开头重新执行**，
   节点内 interrupt 之前的副作用会重跑。幂等必须落在**工具副作用边界**，
   而不是 Agent 的 cursor 上。

### 6.2 修复后的五张执行状态表

> **实现快照（2026-08-16）**：迁移 `20260816_0014` 已新增四张 Agent 子表，
> 并给既有 `agent_runs` 增加 `workflow_type`。普通问答默认 `answer`，当前固定图使用
> `literature_review`；数据库 CHECK 阻止未知工作流悄悄进入执行器。

```sql
CREATE TABLE agent_runs (
    id              UUID PRIMARY KEY,
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    goal            TEXT NOT NULL,
    workflow_type   TEXT NOT NULL DEFAULT 'answer'
        CHECK (workflow_type IN ('answer','literature_review')),
    status          TEXT NOT NULL
        CHECK (status IN ('queued','planning','awaiting_approval','executing','reflecting',
                          'waiting_human','done','failed','cancelled','budget_exceeded')),
    worker_id       TEXT,
    lease_until     TIMESTAMPTZ,
    heartbeat_at    TIMESTAMPTZ,
    -- 预算与熔断（CLAUDE.md 约束 5）
    budget_tokens   INT NOT NULL DEFAULT 200000,
    budget_calls    INT NOT NULL DEFAULT 40,
    budget_wall_ms  INT NOT NULL DEFAULT 300000,
    used_tokens     INT NOT NULL DEFAULT 0,
    used_calls      INT NOT NULL DEFAULT 0,
    next_seq        BIGINT NOT NULL DEFAULT 1,   -- run_events 的序号发号器
    started_at      TIMESTAMPTZ,
    finished_at     TIMESTAMPTZ,
    error           TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 逻辑步骤：计划里的一行
CREATE TABLE agent_plan_steps (
    id          UUID PRIMARY KEY,
    run_id      UUID NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    step_idx    INT  NOT NULL,
    description TEXT NOT NULL,
    tool        TEXT,
    depends_on  INT[] NOT NULL DEFAULT '{}',
    status      TEXT NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending','running','done','failed','skipped')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (run_id, step_idx)
);

-- 每次尝试：同一步骤可以有多次
CREATE TABLE agent_attempts (
    id              UUID PRIMARY KEY,
    run_id          UUID NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    plan_step_id    UUID REFERENCES agent_plan_steps(id) ON DELETE CASCADE,  -- planner 阶段为 NULL
    attempt_no      INT  NOT NULL,
    node            TEXT NOT NULL,       -- 固定图直接记录具体节点名，通用图未来再扩展
    tool_name       TEXT,
    tool_args       JSONB,
    tool_result     JSONB,
    status          TEXT NOT NULL
        CHECK (status IN ('ok','retry','failed','skipped','fallback')),
    idempotency_key TEXT,              -- 指向 tool_invocations
    latency_ms      INT,
    tokens          INT,
    error_model     TEXT,              -- 面向模型的错误信息（约束 4）
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    -- NULLS NOT DISTINCT：planner 阶段 plan_step_id 为 NULL 时约束依然生效（PG15+）
    UNIQUE NULLS NOT DISTINCT (run_id, plan_step_id, attempt_no, node)
);

-- ★ 幂等真正的落点：工具副作用去重
CREATE TABLE tool_invocations (
    idempotency_key TEXT PRIMARY KEY,  -- hash(run_id, plan_step_id, tool_name, canonical(args))
    run_id          UUID NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    tool_name       TEXT NOT NULL,
    args_hash       TEXT NOT NULL,
    result          JSONB,
    status          TEXT NOT NULL
        CHECK (status IN ('in_flight','succeeded','failed')),
    lease_owner     TEXT,              -- worker id；只有租约持有者可结算
    lease_until     TIMESTAMPTZ,       -- worker 崩溃后可回收的租约
    retry_count     INT NOT NULL DEFAULT 0,
    effect_ref      TEXT,              -- 下游幂等键 / 文件版本 / 外部操作 ID
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    completed_at    TIMESTAMPTZ,
    CHECK (status <> 'in_flight' OR (lease_owner IS NOT NULL AND lease_until IS NOT NULL))
);
```

worker 用条件 UPDATE 从 `queued` 或租约已过期的可恢复 run 抢占执行权，并定期更新
`heartbeat_at/lease_until`。watchdog 处理过期 run：尚未开始的任务重新入队；普通问答生成中
断线则把消息/run 标为 `failed`，由用户显式重试；已有 checkpoint 的 Agent run 才能从最近
checkpoint 恢复。不能把“worker 崩溃”伪装成仍在运行，也不能无条件重发一次可能已计费的
模型调用。页面关闭不影响租约，worker 会继续执行。

### 6.3 副作用幂等协议

有副作用的工具（`write_note` 等）执行前必须走这个协议：

```sql
-- 1. 抢占
INSERT INTO tool_invocations
    (idempotency_key, run_id, tool_name, args_hash, status, lease_owner, lease_until)
VALUES ($key, $run, $tool, $hash, 'in_flight', $worker, now() + interval '30 seconds')
ON CONFLICT (idempotency_key) DO NOTHING
RETURNING idempotency_key;

-- 2a. 抢到（有返回）→ 真正执行工具，完成后 UPDATE status='succeeded', result=...
-- 2b. 没抢到 → 读已有行：
--     succeeded → 直接返回存储的 result，不重复执行 ★
--     in_flight 且租约未过期 → 等待或报冲突
--     failed / 过期 in_flight → 用 CAS UPDATE 换新 lease_owner/lease_until，retry_count+1
```

抢占和回收都用条件 `UPDATE ... WHERE status='failed' OR lease_until < now()`，
不允许先 SELECT 再 UPDATE。worker 执行期间必须续租，结算时校验 `lease_owner`。

**边界声明**：Postgres 中的幂等记录无法与任意外部副作用形成一个原子事务。
如果副作用已成功，进程却在写 `succeeded` 前崩溃，单靠这张表无法判断是否已执行。
所以对外工具必须把同一 `idempotency_key` 传给下游；
`write_note` 使用“临时文件 + fsync + 原子 rename + 写入 effect_ref”。
该机制提供的是有明确边界的 **effectively-once**，不宣称对任意外部系统实现理论上的 exactly-once。

当前本地 Markdown 实现还补了一条崩溃恢复口：若进程在原子 rename 成功后、
`status='succeeded'` 落库前退出，租约回收后的重试先比较目标文件 SHA-256；内容已经一致时
只补数据库结算，不再次 replace。输出路径必须是 `AGENT_OUTPUT_PATH` 下的相对 `.md` 路径，
`..`、绝对路径、非 Markdown 后缀和 symlink 逃逸全部 fail-closed。

```sql
ALTER TABLE agent_attempts
    ADD CONSTRAINT fk_attempt_invocation
    FOREIGN KEY (idempotency_key) REFERENCES tool_invocations(idempotency_key);
```

## 7. run_events ★ P0-4 修复

重构前 SSE 协议只在文字里说"事件带递增 seq，重连时续发"，
但既没有事件信封字段，也没有可回放的持久化事件源——**需求成立，实现无处落脚**。

```sql
CREATE TABLE run_events (
    run_id     UUID   NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    seq        BIGINT NOT NULL,
    type       TEXT   NOT NULL,        -- message.delta | citation | plan | step.update | ...
    payload    JSONB  NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (run_id, seq)
);
CREATE INDEX idx_run_events_time ON run_events (run_id, created_at);
```

**seq 发号**：`UPDATE agent_runs SET next_seq = next_seq + 1 WHERE id = $1 RETURNING next_seq - 1`。
发号、写 `run_events`、更新 `messages` / Agent 投影必须在同一事务内完成；
事务提交后再发 Redis/PG 通知。通知只负责唤醒，不承载真相。
单 run 默认由单 worker 写入，即使发生重试，数据库行锁仍保证 seq 唯一。

**这张表同时服务三件事**（一份数据三处复用）：

| 用途 | 怎么用 |
|---|---|
| SSE 续传（B2） | `GET /runs/{id}/events?after_seq=N` 先补发历史再续流 |
| 刷新恢复（B1） | 重进时按 seq 回放已有事件，重建部分输出与中断状态 |
| Agent 时间线（B3） | 前端直接消费事件流渲染，与实时路径同一套逻辑 |

SSE 服务端不得“查完历史后才订阅”，否则两步之间有丢事件窗口。
正确顺序是：先订阅唤醒通知 → 按 `seq > cursor` 补数据库历史
→ 等通知 → 每次醒来再按 `seq > cursor` 查库。
即使通知丢失，超时轮询也会从数据库补齐。

**普通对话也走 run**：非 Agent 的问答同样创建一条 `agent_runs`（goal = 用户问题），
这样 B1/B2 的恢复逻辑只有一套，不需要为对话和任务分别实现。

```sql
-- 表定义顺序导致 messages 早于 agent_runs，初始迁移在此补 FK
ALTER TABLE messages
    ADD CONSTRAINT fk_message_run FOREIGN KEY (run_id) REFERENCES agent_runs(id) ON DELETE SET NULL;
```

## 9. 三种删除语义 ★ P1-f 修复

重构前 `ON DELETE CASCADE` 与"所有文档时序软删除"互相矛盾。明确区分：

| 语义 | 触发 | 行为 | 检索可见性 |
|---|---|---|---|
| **用户删除** | 用户在资料库页删除 | 同一事务内设 `documents.deleted_at = now()` + 所有 chunks `is_searchable=false` | 不可见 |
| **源同步删除** | connector 发现源文件已不存在 | 同一事务内设活跃版本 `invalid_at=now()` + chunks `is_searchable=false` | 不可见 |
| **物理清理** | 手动运维命令 `purge` | `DELETE FROM documents` → CASCADE 到版本/块/chunk | 彻底消失 |

**关键区别**：前两种保留历史，因此 `temporal` 类问题（"我上个版本的笔记怎么写的"）
和历史消息的引用溯源依然成立；只有 `purge` 才真正触发 CASCADE。

`sources` 用 `ON DELETE RESTRICT`：必须先处理其下的文档，防止误删数据源连带清空语料。

## 10. sparse 向量的处理 ★ P1-b

bge-m3 的 dense 和 sparse 是**同一次前向同时输出**的，存储成本接近零。
但 JSONB 上没有可用的高效稀疏检索索引。

**决策**：**生成即存，v1 不建检索路径。**

- 现在不存 → 将来要用就得重跑全量 embedding（几万 chunk 是小时级）
- 现在建检索路径 → 要自己实现稀疏倒排与打分，v1 性价比低

v1 检索路径只有两路：dense 向量 + 词法检索。
sparse 作为 M2 之后的可选第三路，届时评估 `pgvector` 的 `sparsevec` 类型或外部方案。

### 事实组 × 等价证据 → chunk 的映射规则

评测时把标注区间映射成"该策略下哪些 chunk 算相关"，
算法见 [06 §2.1](06-评测体系.md)。核心思想：

```
chunk c 命中事实组 R ⟺ ∃g ∈ R.alternatives:
                          overlap(c, g) / len(g) ≥ 0.5
```

历史字段名 `span_recall` 为兼容报告保留，benchmark-v2 起实际分母是**事实组数**；
同一事实在摘要、正文、结论重复出现时，命中任一人工确认的 alternative 即算覆盖。
事实组 recall（“回答所需事实有几个被召回了”）
比 chunk-id recall 更贴近用户感知，但它单独使用仍会奖励过大 chunk。
E1 的主口径因此是**固定检索 token budget 的 span recall**，
并同时报告 context precision、冗余率与端到端质量，详见 [06 §2.1](06-评测体系.md)。

## 12. 成本与反馈

```sql
-- 公网 demo 的每日费用硬上限。调用前原子预留，调用后按实际成本结算。
CREATE TABLE daily_cost_budgets (
    budget_date  DATE PRIMARY KEY,
    limit_usd    NUMERIC(12,6) NOT NULL CHECK (limit_usd >= 0),
    reserved_usd NUMERIC(12,6) NOT NULL DEFAULT 0 CHECK (reserved_usd >= 0),
    spent_usd    NUMERIC(12,6) NOT NULL DEFAULT 0 CHECK (spent_usd >= 0),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    CHECK (spent_usd + reserved_usd <= limit_usd)
);

-- 每次预留必须有身份，才能幂等结算并处理 worker 崩溃；不能只改聚合计数。
CREATE TABLE cost_reservations (
    idempotency_key TEXT PRIMARY KEY,
    budget_date     DATE NOT NULL REFERENCES daily_cost_budgets(budget_date),
    run_id          UUID REFERENCES agent_runs(id) ON DELETE SET NULL,
    estimated_usd   NUMERIC(12,6) NOT NULL CHECK (estimated_usd >= 0),
    actual_usd      NUMERIC(12,6),
    status          TEXT NOT NULL
        CHECK (status IN ('reserved','settled','released','charged_estimate')),
    expires_at      TIMESTAMPTZ NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    CHECK (actual_usd IS NULL OR (actual_usd >= 0 AND actual_usd <= estimated_usd)),
    CHECK ((status IN ('reserved','released') AND actual_usd IS NULL)
        OR (status IN ('settled','charged_estimate') AND actual_usd IS NOT NULL))
);
CREATE INDEX idx_cost_reservation_expiry
    ON cost_reservations (expires_at) WHERE status = 'reserved';

CREATE TABLE llm_calls (
    id            UUID PRIMARY KEY,
    trace_id      TEXT NOT NULL,
    run_id        UUID REFERENCES agent_runs(id) ON DELETE SET NULL,
    eval_run_id   UUID REFERENCES eval_runs(id) ON DELETE SET NULL,
    task_type     TEXT NOT NULL,
    tier          TEXT NOT NULL CHECK (tier IN ('light','main','heavy','external')),
    model         TEXT NOT NULL,
    provider      TEXT NOT NULL,
    was_fallback  BOOLEAN NOT NULL DEFAULT false,   -- P1-i
    prompt_tokens INT NOT NULL,
    output_tokens INT NOT NULL,
    cached        BOOLEAN NOT NULL DEFAULT false,
    cache_type    TEXT CHECK (cache_type IN ('exact','semantic','prompt')),
    latency_ms    INT NOT NULL,
    ttft_ms       INT,
    -- 成本口径见 07 §7：批处理下按 GPU wall time 摊销，不能用 latency × 单价
    cost_usd      NUMERIC(10,6),
    batch_id      UUID,                   -- 同批并发调用共享一次 GPU 计时
    success       BOOLEAN NOT NULL DEFAULT true,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_llm_task  ON llm_calls (task_type, tier, created_at);
CREATE INDEX idx_llm_batch ON llm_calls (batch_id) WHERE batch_id IS NOT NULL;

CREATE TABLE feedback (
    id           UUID PRIMARY KEY,
    message_id   UUID NOT NULL REFERENCES messages(id) ON DELETE CASCADE,
    rating       SMALLINT NOT NULL CHECK (rating IN (-1, 1)),
    reason       TEXT CHECK (reason IN ('factual','citation','should_refuse','format','slow','other')),
    comment      TEXT,
    promoted_to_eval BOOLEAN NOT NULL DEFAULT false,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

费用预留与结算都必须是数据库事务，并使用稳定的 `idempotency_key`：首次预留时
插入 `cost_reservations`，再条件更新当日 `reserved_usd`；重复请求读取原记录，
不得二次扣减。成功后把 `reserved_usd -= estimated`、`spent_usd += actual`，并把记录
改为 `settled`。只有确认**尚未发给 provider** 的失败才可 `released`；调用超时或
worker 崩溃导致结果不明时，过期回收任务按 `estimated_usd` 计入 `spent_usd` 并标为
`charged_estimate`，宁可保守少放流量，也不能把可能已经发生的费用当成零。

`estimated_usd` 必须按已知输入、provider 最新价格和 `max_output_tokens` 计算成保守上界，
因此正常结算要求 `actual_usd <= estimated_usd`；价格未知或已过期时拒绝发起调用。
预算日期按配置的计费时区生成，不使用各 worker 的本地时区。

## 13. 全局约定

| 约定 | 说明 |
|---|---|
| **时间戳** | 全部表都有 `created_at`；**会被更新的表**才有 `updated_at`（用触发器维护）。纯追加表（`parsed_blocks` / `parsed_block_locations` / `run_events` / `agent_attempts` / `llm_calls` / `feedback` / `eval_results`）只有 `created_at` |
| **枚举用 CHECK** | 不用 PG enum 类型（改起来要 ALTER TYPE，迁移麻烦），用 `TEXT + CHECK` |
| **标注锚点** | gold 标注、引用溯源一律锚在 `parsed_blocks` 的 NFC Unicode code-point 区间，**绝不锚 chunk_id** |
| **每策略独立向量索引** | 部分索引 + `hnsw.iterative_scan`，见 §4.1 |
| **副作用幂等** | 落在 `tool_invocations`，不靠 Agent cursor，见 §6.3 |
| **事件溯源** | `run_events` 是 SSE 续传、刷新恢复、时间线渲染的唯一真相源 |
| **检索可见性** | `chunks.is_searchable` 是唯一查询开关；版本激活、文档删除/恢复与 chunk 投影必须同事务 |
| **删除三语义** | 用户删除 / 源同步删除 / 物理清理，见 §9 |
| **实验可复现** | `config_hash` + `git_sha` + `actual_models` + `fallback_enabled` |
| **UUID v7** | 时间有序，B-tree 局部性好于 v4 |
