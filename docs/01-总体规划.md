# 01 · 总体规划

## 1. 定位

> **2026-08-22 更新**：形态从"要发公网 demo 的 Web 服务"转成**桌面应用**，
> 产品叙事随之收敛（[ADR-0012](adr/0012-退役postgres与redis改用本机文件.md)、
> [ADR-0013](adr/0013-沉浸阅读作为工作模式而非第二条产品线.md)）。

**WorkPilot = OpenWorker 的手 + DeepTutor 的眼睛。**

两个参照物做的是同一件事的两半：

- **OpenWorker** —— 本机 Agent 工作台。一个能跑工具的循环，加上让它敢在你自己硬盘上动手
  的那一整套东西：目录授权、逐次审批、幂等、Scheduler、Inbox、Skills、MCP。
  强在**做事**，但它对"依据"没有承诺——工具返回什么，模型就说什么。
- **DeepTutor** —— 可溯源的文档阅读。侧边一个阅读器，模型每下一个论断就把页面滚到依据
  那一页并高亮。强在**接地**，但读完之后什么也做不了。

合起来才是这个产品：**一个能读懂你的文档、并且据此动手的本机 Agent。**

它不是把两个应用装在一起。阅读是同一个 run 的一档工作模式（`office` / `reading`），
和办公档共用一套工具循环、审批、预算与 checkpoint——所以"读完这篇论文，把结论写进我的
周报"是**一次** run，不是两次。

### 设计哲学

> 功能宽度不加分，可测量的质量才加分。

宁可只做 4 个场景但每个都有对照实验和指标，也不做 10 个场景全靠演示视频。
这决定了本项目所有的取舍。

### 为什么面向个人（而不是企业团队）

这是一个刻意的选择，不是能力妥协。三条理由：

1. **评测数据是真的。** 语料是我自己读过的资料，所以我能亲手标注 gold answer 和 gold span。
   企业场景只能用合成数据，标注质量存疑，面试官一问数据来源就露怯。
2. **badcase 来自真实使用。** 我每天用它，反馈闭环里流的是真实失败样本，不是编的测试用例。
   "效果评估与反馈优化闭环"这件事，只有真有用户才转得起来——而个人产品的用户门槛是 1。
3. **产品思维有落点。** 自己是用户，才知道哪个交互别扭、哪次回答让人不敢信。
   这比对着想象中的企业用户做需求分析真实得多。

**技术栈与企业场景 100% 重合**（RAG / Agent / 记忆 / 评测 / 成本治理），
差别只在权限模型和多租户——而这两点作为**明确的扩展点**记录在
[02 架构设计 §7](02-架构设计.md)，面试时能说清"要支持团队需要补什么"即可覆盖。

## 2. 目标用户与场景

**用户画像**：知识密集型的个人——研究生、独立开发者、需要持续读文献/看行业资料的职场人。
共同特征是**存的比读的多，读的比记住的多**。

选场景的唯一原则：**必须有明确的对错，才能被评测。**
开放式闲聊、创意写作一律不做——它们无法进入质量闭环。

场景按用户在开场界面选的那一档组织。**两档共用同一个 run**，所以跨档的任务
（"读完这篇再把结论写进周报"）不是两次对话。

### 阅读档（`reading`）｜DeepTutor 那一半

**A｜单文档精读**

> "这篇第三节到底在论证什么？它凭什么说负样本要 hard？"

- 侧边阅读器打开这份文件，模型每下一个论断就把页面滚到依据那一页并高亮
- 论断后面跟 `[p.12]`，可点
- **没读过就是不知道**：搜索返回的片段不能当引文，必须先 `read_material` 读到原文
- 文档答不了的要直说答不了，补充文档之外的知识必须标明那是文档之外的

**B｜跨文档检索问答**

> "我读过的论文里，谁在做负样本构造？"

- 挂载的知识库里做 dense + BM25 混合检索，答案带引用到文件 + 页码
- 挂了 KB 就有**确定性预检索**：run 起始先检索一遍折进前缀，弱模型不调工具也已经接地
- **拒答**：库里没有就明确说没有，而不是用通用知识糊弄

### 办公档（`office`）｜OpenWorker 那一半

**C｜多步任务执行**

> "把我这个月读的 8 篇 RAG 论文整理成一份综述，按方法分类，标出彼此差异，存进笔记库"

- 可选计划模式：先出方案 → 用户批准 → 才翻转到可写；批准是 checkpoint 里 `mode` 的翻转，
  不是 prompt 约定
- 每步可见、可中断、可续跑；写操作与外发操作逐次审批
- 模型自己维护任务清单（`todo_write`），不是预先分解好的固定流程

**D｜本地文件与外部系统**

> "把这份 Word 的结论改得更精炼，并更新 Excel 汇总公式"
> "把这个仓库这周的改动整理成一条飞书消息发到项目群"

- 会话级目录授权 + 能力授权；原子写入、冲突检测、有界备份
- Shell（含后台任务）、只读 git、受控浏览器、5 个官方连接器、MCP
- Scheduler 无人值守跑批 + 跨会话 Inbox

### 🔭 长期蓝图｜主动关联与每日 digest

> "今天读的这篇，和你三个月前标记过的 X 是同一问题的两种解法"

个人知识图谱 × 新入库内容 → 关联度排序；每日 digest。
**尚未实现**，不要在简历里冒充已上线能力。

## 3. 成功标准（可量化）

这些数字是简历和面试的全部弹药，必须真实跑出来。
**"目标"列是立项时的期望值，最终以实测为准，做不到就如实写实测值并解释原因。**

| 维度 | 指标 | 基线（朴素向量检索） | 目标 |
|---|---|---|---|
| 检索 | Recall@10 | 待测 | 基线 +15pt 以上 |
| 检索 | nDCG@10 | 待测 | 基线 +12pt 以上 |
| 生成 | 答案正确率 | 待测 | ≥ 80% |
| 生成 | 引用准确率（引用确实支撑答案） | 待测 | ≥ 90% |
| 生成 | 不可答问题正确拒答率 | 待测 | ≥ 90% |
| Agent | 多步任务成功率 | 待测 | ≥ 75% |
| Agent | 失败任务的自动恢复率 | — | ≥ 50% |
| 记忆 | 开/关长期记忆对任务成功率的增益 | — | 有可测量差异即可（**负结果也算成功**） |
| 评测 | LLM Judge 与人工标注一致率 | — | ≥ 85% |
| 成本 | 单次会话成本 | 全大模型档 | 下降 ≥ 60%，质量不衰减 |
| 性能 | P95 端到端延迟 | 待测 | ≤ 5s（首 token ≤ 1.5s） |
| 工程 | CI 门禁拦截的负优化次数 | — | 有真实案例即可 |
| 产品 | 作者自己的日活天数 | — | ≥ 30 天连续使用（dogfooding 的硬证据） |

**交付层面的成功标准**：

- 开源仓库 README 完整、架构图清晰、**一条命令可本地启动**（现在真的是一条：
  `uv run uvicorn`，没有容器，没有外部服务）
- 2 篇技术博客 + 1 个 3 分钟 demo 视频
- ⚠️ **"有公网可访问的 demo"这一条已经不再自动成立。** 转成桌面产品之后，产品的全部
  价值在于它读用户**自己机器上**的文件，而这件事在公网 demo 上做不到，也不该做到。
  三条替代路径与各自的代价见 [02 §5](02-架构设计.md)，**尚未决定**。

## 4. 明确的非目标

写清楚不做什么，比写做什么更能体现判断力。面试被问到时这也是加分项。

- ❌ **不做多用户与权限系统**：单用户产品。扩展点已记录，但不实现
- ❌ **不做通用低代码工作流编排**：那是 Dify 的赛道，本项目是垂直产品
- ❌ **不做模型预训练**：最多在 M2 做一次小模型 SFT 试验，且不做完不写进简历
- ❌ **不做移动端**：Web 响应式即可
- ❌ **不做笔记编辑器**：不和 Obsidian/Notion 抢阵地，只做它们的读取与写回
- ❌ **不追求高并发**：单用户产品，能说清瓶颈在哪即可

## 5. 里程碑

长期蓝图不限在 6 周内全部实现。当前 6 周的开发范围以
[11 MVP 边界](11-MVP边界.md) 为唯一约束源，详细任务见 [09 排期与任务清单](09-排期与任务清单.md)。

| 里程碑 | 周次 | 核心交付 | 硬门槛 |
|---|---|---|---|
| **M0** | W1–W2 | 资料入库 + 基础 RAG 问答 + 引用 + 前端流式 + 安全边界 + 评测基线 | 第 2 周末必须有本地完整闭环和基线数字 |
| **M1** | W3–W4 | 混合检索 + rerank + 固定综述工作流 + 评测集渐进扩充 + Judge 校准 | 拿到第一批“提升了多少”的真实增量 |
| **M2** | W5–W6 | 三档路由或长期记忆二选一深挖 + CI 门禁 + 博客视频 | 实验台账有厚度，含负优化案例 |

**贯穿全程的隐藏里程碑：从 W1 起自己每天用。**
dogfooding 天数本身就是成功标准之一，也是 badcase 的唯一来源。

## 7. 语料方案

**核心优势：全部是我自己真实读过的资料，因此有能力亲手标注。**

| 类型 | 来源 | 用途 |
|---|---|---|
| 学术论文 PDF | arXiv 已读文献（含公式、表格、多栏排版） | 解析能力的试金石；多跳与表格类问答 |
| 个人笔记 | Obsidian / Markdown 笔记库 | 时效性问答（笔记会被反复修改）、写回目标 |
| 网页剪藏 | 浏览器书签 / 收藏文章 | 噪声最大的一类，考验清洗 |
| 电子书与课程资料 | PDF / EPUB | 长文档的层级分块 |
| 技术文档 | 常用开源项目文档 | 多版本时效性对比 |

**规模下限**：500 篇文档。低于这个量级检索指标会虚高（R9）。

**关于合成数据**：本项目**不需要**合成语料。
如果为了扩充规模引入公开数据集，必须在 README 与面试中明确区分「真实个人语料」与「补充公开语料」的比例。
