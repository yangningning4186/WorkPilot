# 02 · 架构设计

> **2026-08-22 大修**：PostgreSQL、Redis、Arq、pgvector、MinIO 全部退役，状态落到本机文件
> （[ADR-0012](adr/0012-退役postgres与redis改用本机文件.md)）；`app/rag/` 的问答流水线
> 收缩成本地知识库，沉浸阅读并成 Cowork 的一档工作模式
> （[ADR-0013](adr/0013-沉浸阅读作为工作模式而非第二条产品线.md)）。

## 0. 一句话

**WorkPilot = OpenWorker 的手 + DeepTutor 的眼睛。**

两个参照物做的是同一件事的两半：OpenWorker 有一个能在你自己硬盘上动手的工具循环，
但它对"依据"没有承诺——工具返回什么，模型就说什么；DeepTutor 每下一个论断就把阅读器
滚到依据那一页，但读完之后什么也做不了。

合起来才是这个产品：**一个能读懂你的文档、并且据此动手的本机 Agent。**
它不是把两个应用装在一起，而是同一个 run 的两档工作模式，共用一套工具循环、审批、
预算与 checkpoint。

**为什么模型网关单独画一层**：它是整个成本治理主线的落点，也是三层架构的最底层——
它是一个独立的 Python 包，依赖表里没有 sqlalchemy / fastapi / pydantic-settings，
因此在**构建期**就不可能反向依赖业务（[ADR-0011](adr/0011-三层架构与依赖方向.md)）。
业务代码不感知模型，路由策略是声明式配置——这样"换一档模型"是改配置而不是改代码。

**唯一的豁免**：KB 的 embedding 直连本机 Ollama，不过网关。那条链路没有 API 花销也没有
配额，网关能管的东西在这里一件也没有；代价是 embedding 不进成本看板
（[04 §3.8](04-知识与阅读设计.md)）。换成云端 embedding 就必须接回来。

## 2. 关键请求时序

### 2.1 Cowork run：一个工具循环

LangGraph 仍在，但已经**不是** planner/executor/reflector 三节点图，而是两节点的
`decide ⇄ execute_tools`——固定工作流那套在真实使用里输给了让模型自己决定下一步。
图的价值现在只剩 checkpoint 与可恢复性，编排本身是循环不是流程。

```
用户下达任务（office / reading 二选一）
  │
  ├─→ run 起始装配 system prompt（这一整段在 run 内不变，因此吃 provider 前缀缓存）
  │     ├ 基座 + 工具说明 + 环境块
  │     ├ 记忆快照（本会话可见的那部分）
  │     ├ 工作模式 playbook（选了阅读才注入）
  │     └ ★ 确定性预检索：挂了 KB 就先检索一遍，命中折进前缀（[K1..Kn]）
  │
  ├─→ 循环 decide：
  │     ├ 末尾挂 session_state 临时块：任务清单 / 当前目录 / 已授权能力 / 计划模式提醒
  │     │   （分界依据是"这一次 run 里会不会变"——会变的放进 system 等于每轮作废前缀）
  │     ├ 选工具 + 生成参数
  │     └ 空转熔断：同一调用签名超 3 次不再执行；连续 2 轮整批重复就收回全部工具
  │
  ├─→ execute_tools（注册表入口，没有旁路）：
  │     ├ 校验 capability + extra_capabilities
  │     ├ 一次性 call-id 审批（三档：计划模式 / 逐次审批 / 免审批）
  │     ├ 裁剪目录的 allowed 白名单
  │     ├ ★ 副作用工具先抢 tool_invocations 幂等租约（已 succeeded 直接复用）
  │     ├ 执行（超时 / 重试 / 降级）
  │     └ 写 checkpoint + agent_attempts → 写 run_events → 推 SSE
  │
  ├─→ 需要人 → waiting_human，进 Inbox（可镜像到飞书）
  ├─→ 需要等时间 → sleeping，让出 worker，到点由调度 tick 原子领回
  │
  └─→ 预算熔断（每步）：token / 调用数 / 墙钟任一超限即终止
```

**核心设计**：Agent 状态是显式的可序列化 dict，每个节点是 `state → state` 的纯函数，
重启后从 SQLite 读回 state 继续。

但**状态恢复不等于副作用不重放**：从 interrupt 恢复时会从节点开头重新执行。
因此幂等必须落在 `tool_invocations` 这一层，而不是 Agent 的 cursor 上
（[ADR-0007](adr/0007-agent幂等与事件溯源.md)）。


## 4. 技术选型与理由

**面试必问：为什么是它？替代方案是什么？为什么放弃？**
这张表的第 3、4 列比第 2 列重要。

| 组件 | 选型 | 替代方案 | 为什么不选替代方案 |
|---|---|---|---|
| Agent 编排 | **LangGraph（退化成两节点循环）** | AutoGen / CrewAI / 自研 | 保留它的理由已经只剩 checkpoint 与可恢复性。固定工作流那套在真实使用里输了：模型自己决定下一步比预先分解的步骤表更有用。**这本身是个值得写的负结果**（[ADR-0001](adr/0001-langgraph-作为-agent-编排引擎.md)） |
| 状态存储 | **SQLite（WAL）** | PostgreSQL / DuckDB | 桌面应用不能要求用户先装容器运行时。SQLite 在标准库里，零依赖零版本风险。代价是写全库串行、无法多进程（[ADR-0012](adr/0012-退役postgres与redis改用本机文件.md)） |
| 消息存储 | **append-only JSONL + SQLite 索引** | 全进 SQLite | 对话是天然 append-only 的，JSONL 可以被任何工具读、可以被 `tail`、损坏尾行可以容忍。索引留在 SQLite 里以支持按 seq/状态查 |
| 向量存储 | **FAISS，一个 KB 一个目录** | pgvector / Qdrant / LanceDB | 索引是**派生数据**，删了重建是秒级——不需要事务保护，也就不需要数据库。安全性由 `manifest.json` 的 embedding 签名承担（[04 §3.1](04-知识与阅读设计.md)） |
| 词法检索 | **BM25（LlamaIndex `BM25Retriever`）** | PG `ts_rank_cd` + zhparser / ES | 换到本地之后，原来"少一个中间件"的理由反而指向 BM25：它是纯 Python 的，而 `ts_rank_cd` 需要一整个 Postgres。**顺带修掉了一个术语错误**——PG 原生是 cover-density 排名，不是 BM25；现在是真的 BM25 了 |
| 索引框架 | **LlamaIndex** | 自写 | 只用它的 `SentenceSplitter` / `VectorStoreIndex` / 两个 retriever，融合与溯源是自己的。它省掉的是 FAISS 持久化与 docstore 那些琐碎的东西 |
| Embedding | **bge-m3（本机 Ollama）** | OpenAI text-embedding-3 | 中英混合与长文本（8k）友好；本地部署，批量灌库不花钱。代价是不进成本看板 |
| 任务队列 | **进程内 asyncio 队列 + 嵌入式 worker** | Arq / Celery | 单用户单进程，队列的唯一消费者就在同一个进程里。持久化真相在 SQLite 的 `queued` 状态上，队列只负责降低唤醒延迟 |
| 缓存 | **进程内 LRU** | Redis | 同上。补全缓存丢了就是多花一次钱，不是数据损失 |
| 桌面壳 | **Tauri 2 + localhost sidecar** | Electron | 体积与内存；Rust 侧只做进程管理与随机 token 注入（[ADR-0009](adr/0009-桌面sidecar与会话级能力授权.md)） |
| 后端 | **FastAPI** | Django / Go | 异步原生、Pydantic 契约、AI 生态全在 Python |
| 前端 | **Next.js 16 + 自写 SSE 客户端** | 纯 React / Streamlit / Vercel AI SDK | 事件契约是自己的（`seq` 断点续传、审批卡片、计划卡片），AI SDK 的抽象反而要绕开 |
| 评测 | **自建 + 借鉴** | Ragas / DeepEval | 评测是本项目的核心差异化，**必须自己实现才能讲透**。借鉴 Ragas 的指标分解与 promptfoo 的快照 diff，但不做壳（[ADR-0003](adr/0003-自建评测框架.md)） |

## 5. 部署拓扑

```
用户的机器（macOS）                    自建推理集群（可选）
┌────────────────────────────┐        ┌─────────────────────────┐
│ Tauri 桌面壳                │        │ Qwen3.5-4B      :8101   │
│   └ Python sidecar :随机端口│ OpenAI │ Qwen3.6-35B-A3B :8102   │
│       ├ FastAPI            │◄兼容──►│ DeepSeek-V4-Flash :8103 │
│       └ 嵌入式 worker       │  协议  └─────────────────────────┘
│                            │        ┌─────────────────────────┐
│ ~/.workpilot/              │        │ 本机 Ollama :11434       │
│   cowork.db                │◄──────►│  bge-m3 embedding       │
│   conversations/*.jsonl    │        └─────────────────────────┘
│   telemetry.db             │
│   kb/<slug>/               │        集群不可用时 ↓
│   *.json (0600)            │        ┌─────────────────────────┐
└────────────────────────────┘        │ 商用 API（对照 + 兜底）  │
      ↑ 没有容器。没有外部服务。        └─────────────────────────┘
```

**公网 demo 的处境变了，必须说清楚。** 立项时"有公网可访问的 demo"是硬性交付标准
（[01 §3](01-总体规划.md)）。转成桌面产品之后这条不再自动成立：整个产品的价值在于它读
用户**自己机器上**的文件，而这件事在公网 demo 上做不到，也不该做到。

替代方案有三条，尚未决定，不要假装已经有结论：

| 方案 | 代价 |
|---|---|
| 录屏 demo + 可下载的安装包 | 门槛最低，但"点开就能玩"的说服力没了 |
| 起一个装了公开语料的只读实例 | 要重新引入服务端形态，等于把刚删掉的那套加回来一部分 |
| 只做 CLI 可复现的评测跑批 | 对技术受众有效，对产品受众无效 |

> 线上如果真的要起，仍然用商用 API 而非自建集群：家里集群不可能 7×24 对公网开放，
> 而 demo 链接挂掉比没有 demo 更糟。自建集群的价值在**离线大批量实验**，不在托管服务。

## 6. 横切关注点

| 关注点 | 方案 |
|---|---|
| 追踪 | 每个请求生成 `trace_id`，贯穿结构化日志与 LLM 调用记录 |
| 错误 | 双通道：`user_message`（给人看）+ `model_message`（给 LLM 看，含修复指引，约束 4） |
| 配置 | Pydantic Settings + `.env`，模型路由表用独立 YAML，改配置不改代码 |
| 时间 | **全程 UTC ISO 字符串**。SQLite 里时间是字符串、比较是字典序，混了本地偏移会让租约与过期清扫判错 |
| 钱 | **整数微美元**。SQLite 没有 decimal，用 REAL 存美元会让 `0.1 + 0.2 != 0.3` 直接发生在预算比较上，而且不报错 |
| 幂等 | 工具副作用按 `tool_invocations.idempotency_key`（不是靠 Agent cursor，[ADR-0007](adr/0007-agent幂等与事件溯源.md)）；跨系统副作用只承诺 effectively-once |
| 互斥 | `os.replace` 是原子的但**不排他**——两个进程都会"成功"。要互斥用 `O_CREAT\|O_EXCL` 建锁文件，过期判定读锁里的 `claimed_at`，不要读 mtime |
| 私有文件 | `core/private_json.py`：先把父目录收到 0700，再写 tmp、chmod、`os.replace`。读失败一律返回 `{}`——一个损坏的配置文件不该让设置页打不开 |
| 安全 | 见 [12 安全与部署](12-安全与部署.md)。写操作与外发操作强制审批 |
| 降级 | 模型档位 fallback 链；集群不可用切商用 API；KB 签名不匹配则**拒绝检索**而不是降级 |

## 7. 多用户扩展点（明确不实现，但要说得清）

本项目是单用户产品（[01 §4 非目标](01-总体规划.md)）。
但"如果要支持团队需要补什么"是面试必问题，答案必须具体到改动点——
**而且退役 Postgres 之后，这个答案变长了，这一点必须诚实说**：

| 维度 | 现状 | 扩展所需改动 | 难度 |
|---|---|---|---|
| **存储** | 单机 SQLite，写全库串行 | **先要把 store 换回一个支持并发写的数据库**。`CoworkStore` 是 Protocol，接口是现成的，但要重写一个实现 | 中，是第一块多米诺 |
| 数据隔离 | 无租户维度 | 引入 `workspace_id`，所有表加维度 + 复合索引 | 低，机械改动 |
| 权限 | 无 | ACL 下沉到片段元数据，**检索前过滤**。关键点：不能检索后过滤，否则 top-k 会被无权文档占满 | 中，设计已预留 |
| 向量索引 | 进程内 FAISS，每个 KB 一份 | 单机 FAISS 无法多进程共享，要换成服务化的向量库（Qdrant） | 中 |
| 并发 | 单用户串行，进程内锁 | `local_run_guard` 的 asyncio 锁跨进程无效，要换成数据库行锁或分布式锁 | 中 |
| 队列 | 进程内 asyncio 队列 | 要换回 Redis/Arq 那一类 | 低，删掉的代码还在 git 历史里 |
| 连接器 | 本地文件 / 5 个官方连接器 | 增加 Slack / Confluence / Drive，需处理 OAuth、增量游标、**权限同步** | 高，权限同步是真难点 |
| 记忆 | 个人记忆 | 分裂为个人记忆 + 团队共享记忆，共享记忆需要写入审核 | 高，是产品问题不是技术问题 |

**架构上仍然预留的**：`CoworkStore` 与 `RagService` 都是 Protocol，检索前过滤的管线位置、
连接器抽象与增量同步机制没有被这次改动破坏。**架构上被这次改动堵死的**：多进程。
这是转成桌面产品换来的，值不值取决于产品往哪走——但不能假装它没发生。
