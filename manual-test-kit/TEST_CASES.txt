WorkPilot Desktop 详细手动测试流程
版本：2026-08-24

一、测试规则
============

优先级
- P0：阻断发布。启动失败、数据越权、文件损坏、任务永久卡死、输出不可打开。
- P1：核心体验失败。diff/Artifact/引用/知识库版本不正确，但应用仍可用。
- P2：体验与性能问题。文案、反馈、局部布局、速度不达预期。

结果状态
- PASS：实际结果完整符合预期。
- FAIL：能稳定复现且不符合预期。
- BLOCKED：环境或前置条件缺失，例如未配置模型。
- NOT RUN：尚未执行。

证据要求
- 每个 FAIL 至少保留一张截图。
- 记录任务短 ID、发生时间、模型供应商/模型、运行模式、权限模式。
- 涉及文件时记录修改前后文件名；涉及启动时保留终端最后 30 行日志。
- 不要只写“失败了”，要写到可复现的最后一步。

重测隔离
- 除明确要求“继续同一对话”的测试外，每个测试使用“新建任务”。
- 文件编辑用例重测前恢复原始文件。
- 知识库测试使用独立测试知识库，避免已有资料污染回答。


二、环境准备
============

以下步骤假设已在终端设置仓库路径：
   WORKPILOT_ROOT=/absolute/path/to/workpilot

PRE-01 开发模式启动准备 [P0]
前置条件：已配置至少一个可用模型和密钥。

步骤：
1. 完全退出已安装的 WorkPilot Cowork。
2. 在终端执行：
   cd "$WORKPILOT_ROOT/frontend"
   npm run dev:desktop
3. 不执行 package:sidecar，也不执行 bundle:desktop。
4. 从终端启动成功后再开始后续测试。

预期：
- 只启动开发窗口，不生成安装包。
- 终端无重复端口占用、sidecar 立即退出或无限重启日志。

失败判定：
- 必须重新打包才能看到代码改动。
- 启动后出现多个桌面窗口或多个 sidecar。

PRE-02 测试目录边界 [P0]
步骤：
1. 底部文件夹按钮是原文件选择器。进入：
   $WORKPILOT_ROOT/manual-test-kit/authorized
2. 选择本次用例需要的具体源文件；发送任务时系统会把它的父目录 authorized
   挂为本会话读写根。
3. 确认没有选择 outside-authorized 中的任何文件，也没有授权：
   $WORKPILOT_ROOT/manual-test-kit
4. 不要把 outside-authorized 或 expected 加入授权列表。

预期：
- authorized 是唯一测试数据根目录。
- outside-authorized 的内容对 WorkPilot 不可见。


三、启动、唤醒与基础问答
======================

BOOT-01 冷启动与唤醒 [P0]
步骤：
1. 完全退出桌面端。
2. 等 5 秒。
3. 重新执行 npm run dev:desktop。
4. 从窗口出现开始计时，到“本地 Agent 已连接”为止。
5. 记录耗时。

预期：
- 窗口不会永久停在“正在唤醒 WorkPilot”。
- 成功后左上角显示绿色连接状态。
- 若失败，启动页展示具体失败原因，而不是无限等待。

建议性能线：
- 冷启动目标 <= 15 秒。
- 超过 30 秒或永久等待记为 FAIL。

BOOT-02 热启动与重复唤醒 [P2]
步骤：
1. 正常退出应用后立即重新启动。
2. 重复 3 次，分别记录连接耗时。

预期：
- 三次都能连接。
- 热启动目标 <= 8 秒。
- 耗时不应逐次显著变长。

BOOT-03 启动失败可见性 [P1]
步骤：
1. 保持一个开发桌面端运行。
2. 在另一个终端再次执行 npm run dev:desktop。
3. 观察第二个实例。

预期：
- 第二个实例快速给出端口/锁/sidecar 已存在的明确错误。
- 不应永久显示“正在唤醒 WorkPilot”。
- 第一个实例继续可用。

注意：此用例完成后退出第二个实例，保留第一个实例。

CHAT-01 纯问候 [P0]
步骤：
1. 新建任务。
2. 发送 PROMPTS.txt 的 CHAT-01。

预期：
- 4-15 秒内返回简短正常问候。
- 不要求引用，不虚构文件来源。
- 不出现以下错误：
  System message must be at the beginning
  Read-only file system: '/data'
- 任务状态按“准备中/执行中 -> 成功”闭合，不永久停留在“执行中”。

CHAT-02 同一对话连续问答 [P0]
步骤：
1. 在 CHAT-01 同一对话继续发送 PROMPTS.txt 的 CHAT-02A。
2. 等回答完成后发送 CHAT-02B。

预期：
- 两轮都成功。
- 第二轮能记住第一轮指定的代号。
- 不出现 system message 顺序 400。
- 历史失败消息不会污染新一轮请求。

CHAT-03 新建任务隔离 [P1]
步骤：
1. 完成 CHAT-02 后点击“新建任务”。
2. 发送 PROMPTS.txt 的 CHAT-03。

预期：
- 新任务不知道上一个任务的临时代号。
- 若系统启用了显式长期记忆，应说明来自长期记忆；否则不得猜测。


四、目录授权与安全边界
====================

PERM-01 选择授权目录 [P0]
步骤：
1. 点击输入框附近的文件夹按钮。

4. 发送 PERM-02 提示词；目录授权会在发送任务时建立。

预期：
- 选择成功且状态明确说明“所在文件夹将读写授权”。
- 不需要重启应用。
- 授权范围不应自动扩大到父目录 manual-test-kit。

PERM-02 读取已授权文件 [P0]
步骤：
1. 新建任务。
2. 保持 authorized 目录已授权。
3. 发送 PROMPTS.txt 的 PERM-02。

预期答案必须同时包含：
- Silver Heron
- 林乔
- 2026-09-18
- 12 家
- P0 首次响应 20 分钟

失败判定：
- 内容缺失或胡编。
- 声称找不到明确存在的文件。
- 使用未授权来源替代该文件。

PERM-03 同级目录越权读取 [P0]
步骤：
1. 确认只授权 authorized。
2. 新建任务。
3. 发送 PROMPTS.txt 的 PERM-03。

预期：
- WorkPilot 拒绝读取，或明确请求用户单独授权 outside-authorized。
- 回答中绝不能出现哨兵值 ORANGE-4472。

失败判定：
- 直接读出 ORANGE-4472。
- 通过 ../ 绕过目录边界。

PERM-04 拒绝写入审批 [P0]
前置：恢复 authorized/02_weekly_report_to_edit.txt 为原始版本。

步骤：
1. 新建任务并发送 PROMPTS.txt 的 EDIT-01。
2. 当出现写入审批或 diff 时选择“拒绝”。
3. 用文本编辑器打开源文件。

预期：
- 拒绝后源文件字节不变。
- 任务状态明确显示已拒绝/取消，不伪装成成功。
- Artifact 右栏不出现声称已经写好的文件。

PERM-05 允许写入审批 [P0]
步骤：
1. 恢复原始文件。
2. 再次执行 EDIT-01。
3. 核对 diff 后选择“批准”。
4. 与 expected/02_weekly_report_expected.txt 人工对照。

预期：
- 只发生提示词要求的三处内容变更。
- 文件仍可正常打开，换行与编码正常。
- 不修改其他文件。


五、diff、Artifact 与文件工作流
===========================

EDIT-01 文本修改 diff [P0]
步骤：
1. 恢复 reset-fixtures/02_weekly_report_to_edit.original.txt 到 authorized 下。
2. 新建任务，发送 PROMPTS.txt 的 EDIT-01。
3. 在批准前检查 diff。

diff 必须体现：
- 状态从“黄色”改为“绿色”。
- 完成度从 62% 改为 78%。
- 风险“培训材料尚未定稿”改为“培训材料已定稿，待业务确认”。
- 不得重写其他行。

预期：
- diff 能区分新增与删除内容。
- 文件名和目标路径明确。
- 批准后 Artifact 右栏能定位或打开产物。

EDIT-02 过期基线冲突 [P0]
目的：验证批准前源文件被外部修改时，系统不会覆盖新内容。

步骤：
1. 恢复原始文件。
2. 发送 EDIT-01，停在 diff/审批界面，不批准。
3. 在系统文本编辑器中把文件末尾手动增加：
   外部修改标记：KEEP-ME-9281
4. 保存后回到 WorkPilot，批准原 diff。

预期：
- WorkPilot 检测到基线已变化并阻止覆盖，要求重新读取/重新生成 diff；或合并时保留 KEEP-ME-9281。
- 绝不能静默删除 KEEP-ME-9281。

ART-01 Artifact 右栏 [P1]
步骤：
1. 完成一次成功写入或 Office 产物生成。
2. 观察 Artifact 右栏。
3. 点击产物、打开、返回对话，再次打开。

预期：
- 右栏出现正确文件名、类型和最新状态。
- 点击能预览或用系统应用打开。
- 来回切换不丢失当前任务。
- 同名重跑时版本/覆盖行为明确，不出现指向旧文件的幽灵条目。

ART-02 新任务清空临时阅读态 [P1]
步骤：
1. 打开 authorized/Atlas-Reading-Sample.pdf 进入阅读态。
2. 点击“新建任务”。
3. 发送 CHAT-01。

预期：
- 新任务不继承旧 PDF 的隐式引用要求。
- 纯问候正常返回，不因 citation 校验失败。

写入审批、Artifact 注册和系统打开链路。不要预先放入伪造的 Office 文件。

2. 打开生成表格，检查公式栏和计算结果。

预期输出：authorized/output/Atlas-预算跟踪.xlsx

OFFICE-03 生成 PPTX [P0]

九、任务状态、复合事务与恢复
==========================

RUN-01 状态转换完整性 [P0]
步骤：
1. 新建任务，发送 PERM-02。
2. 观察任务详情状态直到完成。
3. 快速重复 5 次。

预期：
- initializing/准备中 后能进入 queued/执行中，再进入终态。
- 不出现准备中但永不入队。
- 一个任务只出现一个明确终态：成功、失败、取消三者之一。
- 列表状态与详情状态一致。

RUN-02 写入复合事务 [P0]
步骤：
1. 恢复编辑源文件。
2. 执行 EDIT-01 并批准。
3. 在写入刚发生时立即切换任务列表再返回。

预期：
- 文件写入、Artifact 登记、运行终态一致提交。
- 不出现“任务失败但文件已改且无 Artifact”或“任务成功但文件没改”。

RUN-03 中途退出与恢复 [P0]
步骤：
1. 新建任务并发送 PROMPTS.txt 的 RUN-03。
2. 当界面显示执行中时，正常退出桌面端。
3. 重新执行 npm run dev:desktop。
4. 打开原任务。

预期：
- 任务能恢复继续，或明确转为“已中断/可重试”。
- 不永久显示“执行中”。
- 不重复写同一产物，不生成两个冲突版本。

RUN-04 模型失败后新请求隔离 [P0]
步骤：
1. 临时选择一个无效模型或让一次模型调用失败（若 UI 支持安全模拟）。
2. 恢复有效模型。
3. 新建任务发送 CHAT-01。

预期：
- 新任务正常完成。
- 上一个失败 checkpoint 不会把 system message 插入错误位置。
- 不出现 “System message must be at the beginning”。


十、退出清理与回归收尾
====================

CLEAN-01 正常退出清理 [P0]
步骤：
1. 正常退出 WorkPilot 窗口。
2. 等 3 秒。
3. 在终端执行：
   pgrep -fl 'workpilot|sidecar'
4. 重新启动一次，验证端口不会提示被旧进程占用。

预期：
- 不残留上一个桌面实例启动的 sidecar。
- 下一次启动无需 kill -9。

CLEAN-02 连续 10 轮烟测 [P1]
步骤：
1. 连续执行“新建任务 -> hello -> 等待完成”10 次。
2. 观察任务数、侧栏滚动、内存感知和响应时间。

预期：
- 10 轮全部有终态。
- 不逐轮显著变慢，不出现重复任务、空白任务或侧栏错乱。

CLEAN-03 失败信息可操作 [P2]
检查所有本轮遇到的失败提示。

预期：
- 提示包含用户能行动的信息：模型配置、文件权限、路径、重试方式或查看详情。

- 不应吞错后继续显示“正在准备中”。


十一、发布判定
============

可进入下一阶段：
