# 办公场景路由

先按“用户如何使用产物”选格式，再按任务家族选处理链。扩展名不是内容模型。

## 格式选择

| 使用任务 | 默认格式 | 常见原型 | 不该硬塞进去的内容 |
|---|---|---|---|
| 连续阅读、协作修改、打印成文 | DOCX | 简报、纪要、方案、SOP、研究报告、通知、合同草案 | 大规模行级数据、需要交互计算的模型 |
| 录入、筛选、计算、追踪 | XLSX | 台账、计划、进度、统计、看板、预算/测算、排程 | 长篇论证、只能靠合并单元格维持的表单 |
| 现场讲述、评审、提案 | PPTX | 经营复盘、项目提案、培训、方案评审、故事型分享 | 逐字稿、完整原始数据、无主张的资料摘抄 |
| 冻结分发、归档、对外发布 | PDF | 一页纸、政策速查、正式报告、归档版本 | 需要后续编辑、筛选或重算的内容 |
| 浏览器离线查看、可审计分享 | HTML | 数据报告、研究摘要、审计报告 | 交互式应用、远程依赖、脚本驱动页面 |

用户未指定格式时：文案/纪要/报告优先 DOCX；清单/预算/跟踪优先 XLSX；“汇报/路演/分享”优先
PPTX；“定稿/归档/对外版”优先 PDF；“网页报告/浏览器打开”优先 HTML。

## 任务家族

| 家族 | 判据 | 路径 |
|---|---|---|
| 新建 | 无目标文件；或明确要一份新文件 | Brief → source map → content map → design → 格式 Skill |
| 材料转产物 | 有附件/链接，目标是另一份新文件 | 一次解析材料；保留事实、图表和冲突；再按目标格式重组 |
| 整体重构 | 有原件，要求全文更专业/重排/重做 | 原件作内容来源；另存候选；不把抽象反馈当局部样式值 |
| 局部编辑 | 指定页/节/sheet/range 与明确目标 | 对应格式 existing-file 路径；不重跑全文创作 |
| 审查 | 要求检查、审计、找错 | 只读检查并先报告；只有“检查并修复”才改文件 |

## 高频内容原型

| 原型 | 内容闭环 |
|---|---|
| 管理简报/经营复盘 | 结论 → 偏差 → 原因/风险 → 行动与检查点 |
| 会议纪要/决策备忘 | 已决 → 未决 → 行动（负责人/日期/状态） |
| 方案/提案 | 问题 → 目标 → 方案 → 证据 → 风险 → 路线图/决策请求 |
| 研究/分析 | 问题 → 方法/范围 → 发现 → 解释 → 局限 → 建议 |
| SOP/手册 | 适用范围 → 前置条件 → 步骤 → 验收 → 异常处理 |
| 台账/计划 | 明细输入 → 状态/计算 → 汇总 → 例外/行动 |
| 预算/测算模型 | 假设输入 → 计算链 → 结果 → 敏感性/检查 |
| 培训/知识分享 | 为什么 → 概念 → 示例 → 方法 → 练习/总结 |
| 班会/课堂/工作坊主持 | 目标与引入 → 必要知识 → 示例/体验 → 明确互动 → 复盘 → 班级/团队行动 → 收束 |

命中多个原型时选一个主原型，其余只补必要模块。不要为了展示能力把每种模块都塞进产物。

### 主持型演示不是百科资料

出现“班会、课堂、培训、工作坊、共创、团建、现场互动”时，优先判断用户要的是**主持流程**还是
知识讲解。主持型 PPTX 的验收对象是“拿起来能带现场”，至少包含：

- 可观察的受众结果，而不只是“了解主题”；
- 开场问题/情境或明确承诺；
- 为活动服务的必要知识与例子，不做连续百科段落；
- 至少一个完整互动：可见问题、2–4 个步骤、时限、参与方式和复盘问题；
- 收束后的选择、承诺、行动或带走句。

节日班会通常需要文化内容、体验活动与共同情感三条线。不能把“起源、习俗、诗词”各写一段就
结束；这些内容必须导向猜谜、观察、比较、分享、创作或班级行动。页数按环节与时长决定，不为达到
固定页数拆出一句话页，也不把所有内容压成 5 页空稿。

## 忠实度路由

- **高保真**：合同、政策、对外披露、用户指定模板、材料中的图表/数据。保留原值与边界，不自由补写。
- **适度提炼**：内部汇报、会议纪要、研究摘要。允许重组和删重复，但不改变状态与口径。
- **自由创作**：只有主题、无事实材料的创意或教学内容。仍需标明假设，时效事实先研究。
