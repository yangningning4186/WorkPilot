# 可执行设计系统

设计先表达信息关系，再表达风格。所有约束必须能映射到目标格式能力。

## 共同令牌

| 角色 | 要求 |
|---|---|
| typography | 只定义 title / heading / body / caption 的角色与中英文字体，不用空格或任意缩字调版 |
| color | background / surface / text / accent / positive / warning；正文与背景保持高对比 |
| spacing | 同层级一致、不同层级有明显差异；留白服务分组和强调 |
| emphasis | 每个可见单元只有一个第一视觉焦点，强调色不承担整段正文 |
| visual | anchor（主视觉）、evidence（证据）、atmosphere（氛围）；氛围图不能代替证据 |
| repetition | 同类对象一致；连续页面/章节/sheet 不能机械复制同一构图而不改变信息结构 |

默认只用一个主色、一个浅底色和必要的状态色。颜色越多不等于信息越丰富。

## 格式适配

### PPTX

- 封面/章节/峰值页可 focus；普通页用 standard/dense。
- 先选主张对应的结构：趋势→chart，阶段→timeline，取舍→comparison/matrix，关键数字→big_number，
  并列完整信息→cards，现场练习→activity，流程/循环/层级/漏斗/金字塔→diagram，视觉证据→image_text。
- 只有固定组件无法表达且空间位置本身有意义时才交给受约束 canvas；超过 8 个节点或交叉连线复杂时
  先拆页或改用已核对视觉素材，不把一般关系网塞进自由坐标。
- 图片作为结构元素时应占据可感知面积；低信息量小插画不算主视觉。
- 规划时建立逐页映射：`message → layout → visual role → density → anti-pattern`。
- 封面/章节有可靠素材时用 L1 主视觉；完整写入前先试制封面和代表页并实际看页图。

### DOCX / PDF / HTML

- 先用标题层级、段落、列表、表格、callout 建阅读层级，再考虑装饰。
- 文体决定设计：合同/公文克制，报告突出摘要和关键数据，手册突出步骤与警告。
- 表格只在对齐关系重要时使用；大面积底纹和卡片不能把长文切成碎片。

### XLSX

- 输入、计算、汇总、状态区必须可区分；明细数据仍保持规则表格结构。
- Summary 只放少量关键指标和最多两个图表；图表必须对应可见数据区和一个结论。
- 打印表单不依赖颜色传义；模型类表格通过样式区分假设与公式。

## 反模式

- 用“极简风”解释普通内容页的大面积空白；
- 用卡片包裹每一句话，导致一整页都是空盒子；
- 用无关照片、图标或 AI 插画填空；
- 所有页面都居中、所有章节都同构、所有 sheet 都复制同一种标题区；
- 设计文档写了 Renderer 没有的坐标、动画、母版、条件格式或控件。
