# 成品质量闭环

只验最终保存文件。中间 Markdown、Spec、脚本、HTML 或截图都不是交付物真相。

## 五层检查

| 层 | 要检查什么 | 常见失败后的回退点 |
|---|---|---|
| 内容 | 必需信息、结论、数据、单位、日期、状态、负责人、行动、限制 | source map / content map |
| 结构 | 标题层级、原生表格/公式/图表/notes、对象数量、引用关系 | content map / 格式 Spec |
| 视觉 | 空白/空洞、空容器、溢出、遮挡、截断、低对比、同构重复、失真 | density / layout / design |
| 可用性 | 读者是否能快速找到结论、输入、异常、行动或决策请求 | 场景原型 / 阅读顺序 |
| 证据与安全 | claim 来源、未决状态、敏感内容、外部关系、活动对象 | source map / 安全策略 |

## 空洞检查

“不是空白页”不等于有内容。逐页/逐节/逐 sheet 检查：

- 是否只有标题或一句泛泛表述；
- 卡片、栏位、象限、图表区是否有空容器或明显未利用的内容槽；
- 留白是否服务真正的 focus 主张，还是因为支撑材料没写；
- 主视觉是否承担 anchor/evidence 角色，还是小装饰；
- 连续三个单元是否结构与节奏完全相同；
- 删除这个单元后，读者是否几乎不损失信息。
- 主持型演示是否写清问题、步骤、时限、参与方式和复盘，而不是只有知识段落。

focus 单元允许大量留白，但必须是封面、转场、关键数字、强结论或强视觉；普通 supporting 单元不得
以“简洁”为由缺少 support。

## 修正路由

| 反馈/缺陷 | 先改什么 |
|---|---|
| 太空、太水、像模板 | 补主张支撑、合并弱页、换成信息匹配的结构；再调版式 |
| 太挤、字太小 | 删弱内容、拆页/拆表、转附件；禁止整体缩字 |
| 漂亮但没说清 | 回 content map，补“所以呢”和行动 |
| 数字/状态不对 | 回 source map，核对原值、单位、时间和 confirmed/open |
| 风格不适合场合 | 回 design constraints，不改已确认事实 |
| 文件可打开但不好用 | 回场景原型，重排阅读/输入/决策路径 |

每轮只修导致失败的层，并重新检查完整最终文件。最多两次自动重试；不要只检查改过的页或 sheet。

PPTX 在写最终文件前还要做两次视觉闭环：封面 canary，以及完整 Spec 的代表页预览。预览必须把
真实页图返回给模型查看；只看 Validator 分数或文件可打开，不能替代这一步。最终文件仍需全页
栅格化，试制图不是交付物。

## 交付措辞

分别报告“结构检查”“真实版面预览”“公式重算”“证据检查”是否执行。`not_run` 是未测量，不是通过；
warning 必须原样说明，不能被总分掩盖。
