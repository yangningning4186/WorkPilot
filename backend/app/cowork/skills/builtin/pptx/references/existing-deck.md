# Existing deck

PptxGenJS 能可靠新建演示文稿，但不读取并原位修改任意现有 PPTX。已有 deck 只走下面两条明确路径，
不能静默改用 python-pptx 写入。

## 只读检查

先盘点页数、页面尺寸、主题/母版、notes、图片与外部关系、动画、嵌入对象、目标页文本与形状类型。
Python/OOXML 工具只允许读取、解包、结构校验和栅格化；不得保存回源文件或生成“已编辑”候选。

## 基于原稿重做

把原稿视为材料和视觉参考：一次提取 source map、逐页主张、notes、图表数据和可复用本地素材，选择
Skill 内 `visual_kit`，重新建立 STORY/DESIGN 与 `PresentationSpec`，再由固定 PptxGenJS Renderer
生成**不同文件名**的候选，例如 `<stem>-workpilot.pptx`。不得覆盖原件，也不得声称保留了原母版、
动画、嵌入对象、精确坐标或所有 notes。

用户要求像素级保留母版、动画、嵌入对象或只改某个现有 shape 时，准确说明当前 PptxGenJS 路径不
支持这种保真编辑，并停止写入；只读诊断仍可继续。若用户接受重做，再按完整新建闭环执行。

最终候选必须重新打开，核对页数、尺寸、标题、notes、关系与 ZIP 完整性，并从**最终候选 PPTX**
逐页栅格化。任何不支持对象、溢出或外部关系导致的失败都停止提交。
