# PPTX QA

以最终保存的 PPTX 为唯一验收对象，不验收内存中的 Spec 或中间截图。

1. **生成边界**：确认最终文件由固定 PptxGenJS Renderer 新建；Python 只做 Spec/素材适配、只读
   重开和栅格化，不能写页面，也不能作为 PptxGenJS 失败时的 fallback。
2. **结构**：重新打开文件；核对页数、尺寸、标题、notes、claim/evidence 绑定与外部关系。
3. **内容**：逐页核对 takeaway、layout 必需内容、数字、单位、日期、专名和来源；确认没有空容器、
   占位符、左右栏重复、只报数据不讲含义或重复页面。
4. **视觉**：最终写入前调用 `preview_presentation` 处理代表页，并查看附带的全稿 montage 检查节奏，
   再把每页从最终 PPTX 栅格化。
   视觉模型须实际查看页图，检查缺字方框、溢出、裁切、遮挡、失真、低对比度、过小字号、连续
   同构，以及“非空但空洞”的页面：大容器只有一行、普通页只有标题、主视觉只是角落装饰、无意
   的大面积空白。运行时出现 `<vision_fallback>` 时，纯文本模型只采用结构化渲染结果检查页数、
   溢出、不支持对象、内容容量与重复；不得声称判断过裁切、对比度或整体观感。
5. **兼容性**：确认图片已嵌入、SVG 已转为兼容 PNG、没有远程资源或不支持对象；PptxGenJS 输出可被
   PowerPoint 只读解析器重新打开。
6. **图示语义**：diagram/canvas 逐条核对节点顺序、父子归属、漏斗/金字塔层级、箭头方向与连接线
   标签；确认线在节点下层、标签不被线穿过。几何合法不代表关系正确。
7. **可主持/可决策**：培训、班会、工作坊的 activity 页必须有问题、步骤、时限和复盘；管理/提案页
   必须能找到结论、行动或决策请求。资料存在不等于场景可用。
8. **修复循环**：事实错回 source map，页面太空回 STORY/content map，太挤才缩短或拆页，构图错换
   layout，风格错回 DESIGN；再生成并重新检查全部页面。

只有 Renderer 返回全部页面、`overflow_shapes` 与 `unsupported_shapes` 为空，且视觉模型实际
收到并检查页图后，才能说“已做视觉审阅”。纯文本模型在确定性检查通过后可以交付，但必须准确
报告“结构、内容与逐页渲染检查通过；未进行模型视觉审阅”，并把该项保留为 warning。任何
failed/warning 都不得改写成已通过。
