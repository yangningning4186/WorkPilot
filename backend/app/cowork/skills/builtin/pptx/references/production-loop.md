# 演示文稿生产闭环

这条流程由单一 `pptx` Skill 从材料维护到最终交付。所有动作都必须落到 WorkPilot 当前真实工具、
视觉套件与 `PresentationSpec` 能力上；不要再调用独立 planning Skill，也不要把其它 Renderer 的
组件名、源码格式或实时服务命令带进来。

## 1. 能力盘点

动笔前只确认与本稿相关的能力：

- 有用户材料图：登记本地路径、真实内容、比例、清晰度与用途；
- 当前工具面确实有图片生成能力：可按 `references/images.md` 生成并逐张核对；
- 没有图片生成能力：明确走原生 `chart/cards/activity/timeline/matrix/diagram`，特殊空间关系才用受约束
  `canvas`；或为超过内置图示复杂度且适合矢量表达的主题制作
  安全 SVG；不要声称调用了不存在的工具；
- 有时效事实：先检索并记录来源；无时效要求且用户已给足材料时不额外扩写。

能力不可用是一个路由信号，不是暂停理由。只有缺少会改变内容边界的用户选择时才提问。

## 2. 项目契约

复杂新建任务使用一个独立项目目录，至少保留：

```text
<project>/
├── SOURCE-MAP.md
├── STORY.md
├── DESIGN.md
└── assets/       # 仅在确有本地素材时创建
```

简单短稿可只在上下文维护这些契约；复杂材料任务才写文件。`STORY.md` 决定逐页主张、支撑、页面
功能和节奏；`DESIGN.md` 选择 `visual_kit`、布局映射与素材清单。两者完成后才写 Spec。固定
PptxGenJS Renderer 不需要 `slides/*.slide` 源文件，不为模仿其它工具制造空目录。

## 3. 素材先于页面

在页面 Spec 之前完成素材清单：来源方式、绝对本地路径、真实内容、宽高比、使用页、视觉角色、
是否已核对。需要多张视觉时先统一风格词，再生成/绘制；严禁先放占位符、最后随便补图。

素材优先级：用户材料或可信原图 > 当前环境真实可用的图片生成工具 > 安全 SVG/原生结构。
SVG 是结构图、抽象图形和可可信表达的风格化物件的兜底；不能用几个圆和线冒充人物、办公室、
校园或真实产品场景。

## 4. 封面 canary

完整生成前先验证视觉语言：

1. 只构造一页、使用最终 `visual_kit`/theme 的封面 Spec；有 L1 素材时使用 `title.image_path`。
2. 若 `preview_presentation` 尚未加载，先调用 `load_tools` 加载。
3. 调用 `preview_presentation`。视觉模型查看返回的真实页图；若运行时给出
   `<vision_fallback>`，则读取工具的结构化渲染与校验结果，不要求纯文本模型接收页图。
4. 视觉模型检查主题辨识度、标题层级、主视觉比例、对比度、裁切、风格与场合。纯文本模型只判断
   结构、内容容量、素材登记与确定性检查，不得推断自己看到了裁切或整体观感。
5. 不合格时只修 STORY/DESIGN/素材或封面映射；最多两轮。无视觉能力不是停止条件，但必须选用
   Renderer 的安全标准版式，并把“未进行模型视觉审阅”保留到最终交付。

canary 是内部试制，不登记为交付物。视觉模型不能用一句“已预览”代替查看图片；纯文本模型也
不能把“工具已栅格化”说成“我已查看图片”。

## 5. 完整试制

按 STORY 顺序一次构造完整 Spec。每页提交前核对：

- 页面功能与主张一致；知识页讲清“是什么/为什么”，活动页写清“做什么/多久/如何复盘”；
- `message → support → visual_role → density → layout` 无断点；
- 普通 supporting 页不是标题加空容器；卡片有说明，互动有步骤和复盘问题；
- 相邻页改变信息结构或视觉重量，不连续复制同一种卡片轮廓；
- 图片路径都已授权、内容已核对，来源/口径写入 notes。

调用 `preview_presentation` 处理代表页。视觉模型应优先显式查看：封面、最密内容页、第一张证据/
主视觉页、活动/决策页、结尾。短稿可查看全部页，长稿分批查看，每批不超过 8 页。纯文本模型仍
执行同样的代表页渲染与结构化校验，但不声称查看了返回图片。

## 6. 定向修复与最终写入

从页图发现问题后按原因回退：

| 现象 | 回退点 |
|---|---|
| 太空、像模板 | STORY 的 support / 页面功能；合并弱页或改 `cards/activity/image_text` |
| 只有漂亮装饰 | 素材清单与 visual role；换成能承载主张的 L1 |
| 太挤或字小 | 删弱内容、拆页、换容量匹配的 layout |
| 连续同构 | DESIGN 页面映射；改变关系结构，不只换颜色 |
| 图片不符、裁切错 | 素材本身、宽高比或 `image_fit` |
| 事实/口径错 | source map，不在版式层修文案 |

完整试制通过后才调用 `render_artifact` 写最终 `.pptx`。最终文件仍须通过逐页栅格化、结构、内容、
安全与证据检查；试制页图不能替代最终文件 Validator。纯文本模型缺少的是模型视觉审阅，不是
逐页渲染、结构化校验或交付能力；该缺口必须作为 warning 报告。

## 7. 对用户可见的进度

复杂稿应按「内容大纲 → 风格与素材 → 封面试制 → 逐页制作 → 代表页检查 → 交付」更新进度。
不要暴露 Spec、缓存目录、内部页图文件名或 Renderer API；但也不要长时间只说“正在处理”。
