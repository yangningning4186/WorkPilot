# 场景原型 → 工作簿结构

写 `WorkbookSpec` 之前，先判断用户要的是哪一类表。**不要按行业套模板，按"用户拿它干什么"
选原型**；命中多个就以核心交付目标那个为骨架，其余作补充。全都不命中就按记录型做轻量版，
不主动复杂化。

| 原型 | 用户信号 | 结构 | 关键做法 |
|---|---|---|---|
| 记录型 | 记录、清单、台账、明细、登记 | 单张明细表 | `tables` 一张搞定；`freeze_panes: "A2"`；不做汇总 |
| 计划型 | 计划、排期、里程碑、负责人、交付 | 事项 + 时间 + 负责人 + 状态 | 日期只展示可用 ISO 文本；需日期计算时用 `DATE(...)` cell 公式 + `style: date`；状态列不编造进度 |
| 进度型 | 打卡、完成率、进度、检查项 | 明细 + 完成统计 | 完成率写 `=COUNTIF(...)/COUNTA(...)` 并带除零保护，`style: percent` |
| 统计型 | 统计、汇总、分析、排名、占比 | Summary + Raw 两张 | Summary 全部用公式引用 Raw；需要趋势时加一张 `line`/`column` 图 |
| 看板型 | 看板、一眼看、概览、KPI、汇报 | KPI 区 + 图表 + 支撑明细 | KPI 用 `style: metric` 散点 cell；图表 ≤2 个；明细单独一张 sheet |
| 计算模型型 | 预算、成本、收益、库存、测算 | 输入假设区 + 计算区 + 结果区 | **假设值是 `value`，其余一律 `formula`**；改一个假设全表要跟着动 |
| 日历/排程型 | 日历、月历、周计划、排班 | 日期为行、事项为列 | 需要日期计算时用 cells + `DATE(...)`；不要把 ISO 文本当原生日期，也不要试图做真正月历网格 |
| 表单/打印型 | 打印、签字、填报、申请表 | 标题 + 填写区 + 签字栏 | ⚠️ 见下方限制，先告诉用户能做到什么程度 |

## 这套 Renderer 做不到的事（承诺前先说清楚）

`WorkbookSpec` 没有这些字段，Renderer 也不会生成：

- **合并单元格** —— 表单型的跨列标题做不出来，只能靠 `style: title` 的单个 cell 近似。
- **条件格式** —— "超预算标红"这类要求实现不了。替代：加一列 `=IF(...,"超支","")` 的文本标记。
- **数据验证 / 下拉列表** —— 填报表的受控输入做不到。替代：在表头旁写一格取值说明。
- **普通区域的独立 autofilter 开关、列宽手工指定、打印区域** —— `tables` 会自带筛选按钮；其他
  区域不能单独开筛选。列宽由 Renderer 按中英文显示宽度算，超过 8 列自动转横向。

用户要的是"能打印签字的申请表"或"填错自动变红"时，**先说明这两条做不到**，再问是接受
降级版本，还是改用 docx 出表单。**不要默默交一份少了一半功能的表还说完成了。**

## 公式的两条硬规矩

1. **推导值一律写公式，不写死结果。** 评分和用户体感都取决于"改一个明细，汇总会不会跟着变"。
2. **除法和比率当场带保护**，写在公式字符串里，不是写在注释里：

   ```
   =IF(N(B2)=0, "", B3/B2)          ← 分母可能为 0 或空
   =IFERROR(B3/B2, "")              ← 引用范围不确定时
   ```

   不保护的公式会在 Excel/LibreOffice 重算后出现 `#DIV/0!`。Validator 只保证静态公式与显式错误
   检查；没有 LibreOffice 时不能声称已经验证计算结果。

## 坐标锚点（写 Spec 前先定）

同一 sheet 只要有标题行、多区块、汇总区或图表，就先列出：标题行、表头行、数据起止行、合计行、
图表 anchor。公式和 chart range 全部从这些锚点推导，不能先按“数据从第 2 行开始”写死再改布局。

`cells`、`tables` 与 `charts` 不得无意重叠；Renderer 的顺序是 cells → tables → charts，表格会覆盖同
地址的 cell 值。唯一可控的重叠是：为了给 table 数据列设置 number format，先放同地址的
**style-only cell**（不写 value/formula），再由 table 填值。除此之外，区域重叠一律视为规划错误。

图表数据范围要把系列表头包含进去，因为 Renderer 使用首格作为系列名：例如数值在 `B1:B3`、
类别在 `A2:A3`，则 `data_range="Summary!B1:B3"`，`categories_range="Summary!A2:A3"`。

## 样例数据

- 用户明确要空表/模板/自己填写 → 不放样例；保留表头、填写说明和带空值保护的公式。
- 用户明确要示例/演示 → 放 3–5 行明显虚构且与公式自洽的样例。
- 用户没说清且用途更像可直接演示的成品 → 最多放 3 行样例，并在交付说明中标明。
- 用户给了真实数据 → 全量放进明细表，不裁剪、不"取前 10 行示意"。
- 任何情况下不要用真实姓名、手机号、身份证号编样例。
